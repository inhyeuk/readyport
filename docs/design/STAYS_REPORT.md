# 묵는 곳 (숙소) — 작업 보고 (2026-10-03)

운영자 요청(그대로):

> "호텔 예약 정보도 관리하는 거지?"
> → "날짜별로 숙소가 달라질 수 있으니 이것도 고려해서 작업해줘. … 그리고 숙소는 구글 맵에서 바로 찾아볼 수 있도록 link 되도록 해줘."

## 1. 왜 바꿨나

같은 호텔이 **두 곳**에 흩어져 있었다.

| 예전 | 담긴 것 | 없던 것 |
|---|---|---|
| 예약 서류 한 줄 `BookingRecord(kind="lodging")` | 이름·예약번호·체크인·체크아웃 | **주소** |
| 이동하기의 가는 곳 `Place` | 이름·현지어 주소·좌표 | **날짜** |

그래서 ① 같은 호텔을 두 번 적어야 했고 ② 입국 카드의 숙소 주소 칸은 **언제나 직접 입력**이었고 ③ 날짜별로 숙소가 바뀌는 여행(11/3~11/5 방콕, 11/5~11/7 아유타야)을 담을 자리가 아예 없었다.

## 2. 무엇을 만들었나

### A. 날짜가 있는 숙소 목록

- `VaultContents.stays: List<StayRecord>` — **암호화 보관함**(여권·예약 서류와 같은 파일). 숙소 하나에 이름 · 주소(현지 글자) · 한국어 주소 메모 · 체크인·체크아웃 · 예약번호 · 종류 · 좌표 · 전화 · 메모.
- 한 여행에 0~n곳, **밤마다 다른 숙소**여도 된다. 순수 함수는 `app/src/main/java/com/readyport/stay/Stays.kt`:
  - `forTrip(stays, trip)` 날짜 순 목록 · `covering(date)` 그 날 밤(입실 ≤ 날 < 퇴실 — 옮기는 날은 새 숙소) · `on(date)` 그 날 머무는 곳 · `forArrival(trip)` 도착한 날 묵는 곳(없으면 첫 숙소) · `nights(stay)` 몇 박.
- **부드러운 알림**(`Stays.notes`): 날짜 없음 · 빈 날 · 겹침 · 도착한 날 묵을 곳 없음 · 여행 날짜 밖. 종류마다 한 번만, 저장을 막지 않는다.
- 화면: `ui/stay/StayCards.kt`(묵는 곳 카드·한 숙소 카드), `ui/stay/StayEditScreen.kt`(넣기·고치기, FLAG_SECURE).

### B. 입국 카드 자동 입력

도착한 날 묵는 곳에서 **주소·이름·종류**만 만든다(`FormValues`). 나라별로 지금 채우는 칸과 사이트에서 골라야 하는 칸:

| 나라(양식) | 앱이 채우는 칸 | 사이트에서 직접 골라야 하는 칸 |
|---|---|---|
| 태국 TH_TDAC | `stay.address`(영문 대문자) · `stay.type`(`호텔 → HOTEL`) | 숙소가 있는 주 · 구·지역 · 동·세부 지역 · 우편번호 |
| 말레이시아 MY_MDAC | `stay.address` · `stay.type`(기본 select라 사이트 글자 그대로 `HOTEL/MOTEL/REST HOUSE`) | 주 · 도시 · 우편번호 |
| 싱가포르 SG_SGAC | `stay.address`(길 이름) · `stay.hotel`(이름 — assist) | 우편번호 |
| 인도네시아 ID_ALL_INDONESIA | `stay.address` · `stay.hotel`(assist) | (없음) |
| 대만 TW_TWAC | `stay.address`(호텔 이름 또는 주소 한 칸) | (없음) |
| 일본·중국·필리핀·베트남 | — (레시피가 없는 수동 모드 나라) | — |

- **종류는 그 나라 선택지에 있을 때만** 넣는다. MDAC에는 게스트하우스가 없어서 그런 숙소면 비워 두고 사람이 고른다 — 없는 선택지를 지어내지 않는다.
- 레시피 변경: `stay.address`·`stay.hotel`의 `source`를 `user_input` → `booking`, `confirm`을 `individual` → `bulk`(확인 화면의 `묵는 곳에서` 묶음에 들어간다). 레시피 버전을 올리고 다시 서명했다. **사이트 칸 이름(selector)은 하나도 만들지 않았다** — 서명된 레시피에 이미 있는 칸만 썼다.
- 확인 화면에 안내 카드 하나: **`주소는 넣어 드리고, 지역은 사이트에서 골라 주세요`** + 저장해 둔 주소를 그대로 보여 준다. 채우지 않은 칸을 채웠다고 말하지 않는다(빈 필수 칸은 그대로 빈칸으로 센다).
- `stay.type`은 고르는 칸이라 **초안에 미리 골라 둔다**(`FormValues.suggest`) — 사람이 바꿀 수 있다.
- 숙소 전화번호는 **입국 카드에 넣지 않는다**: 다섯 레시피의 전화 칸은 모두 여행자 본인 휴대폰(`profile.phone`)이고, 숙소 전화 칸을 둔 양식이 없다. 칸 이름을 지어내지 않으려고 저장만 하고 보여 주기만 한다.

### C. 구글 지도 링크

- 공식 문서(developers.google.com/maps/documentation/urls)의 두 주소만 쓴다. **API 키·새 라이브러리·네트워크 호출 없음**, `ACTION_VIEW` 인텐트로만 연다(`stay/StayLinks.kt`).
  - 찾기: `https://www.google.com/maps/search/?api=1&query=<좌표 또는 주소>` (좌표를 알면 `lat,lng`, 없으면 주소, 주소도 없으면 이름, 셋 다 없으면 버튼을 그리지 않는다)
  - 길찾기: 이동하기와 같은 `RideLinker.mapsUrl` = `https://www.google.com/maps/dir/?api=1&destination=…&travelmode=transit`
- **기사님께 보여 주기**도 숙소 줄에서 바로 — 그 숙소를 '가는 곳'으로 맞춰 두고 이동하기 화면을 연다.
- **한 번만 적는다**: 숙소를 저장하면 `Place.id = Stay.id`로 가는 곳이 만들어지고(`PlacesRepository.syncStay`), 주소를 비우거나 숙소를 지우면 그 가는 곳도 사라진다. 사람이 직접 넣은 가는 곳은 건드리지 않는다. 방향은 **숙소 → 가는 곳 한 방향**뿐이다.

### D. 새 메뉴에서의 자리

- 집은 **예약 단계**의 `묵는 곳` 카드(날짜 순 목록 + `숙소 추가` + `예약 서류에서 가져오기`).
- **입국 단계**는 `도착한 날 묵는 곳`(공항에서 꺼낼 주소 + 지도), **여행 중 단계**는 `오늘 묵는 곳`.
- 체크리스트 `address_local`(숙소 주소를 현지어로 저장하기)이 `generic` → **`auto`**(`from: stay_saved`, `action: open_stays`)가 되어, 주소를 적어 둔 숙소가 하나라도 있으면 앱이 스스로 체크한다(사람이 되돌릴 수 있다). `packs/src/index.json` 버전을 `2026.10.03-3`으로 올리고 다시 서명했으며, 스키마에 `stay_saved`·`open_stays`를 더했다.

### E. 예약 서류에서 뽑기

`BookingExtractor`가 숙소 서류에서 **이름과 주소 후보**도 뽑는다(규칙 기반, 기기 안, 한국어·영어).

- 이름: `숙소명`·`호텔명`·`Hotel Name` 같은 라벨 값 → 없으면 `호텔·리조트·게스트하우스·Hotel…` 같은 말이 든 줄. 서류 제목 줄(`호텔 예약 확인서`)·주소 줄은 뺀다.
- 주소: `주소`·`소재지`·`Address`·`Location` 라벨 값(같은 줄 뒤 → 없으면 다음 줄). `이메일 주소`는 주소로 보지 않는다. 라벨은 줄 앞쪽(12글자 안)에서만 찾는다.
- 못 찾으면 **비워 둔다**(지어내지 않는다). 언제나 확인 화면에서 사람이 보고 고친 뒤에만 저장한다.
- 확인 화면에서 종류를 `숙소`로 고르면 저장은 예약 서류 목록이 아니라 **그 여행의 묵는 곳**으로 간다(한 줄로 알려 준다).

## 3. 옮기기 결과 (예전 저장본)

`Stays.migrate`가 보관함을 풀 때 한 번 돌아간다.

- `lodging` 예약 서류 → 묵는 곳. **id를 그대로** 둔다(가는 곳·체크 표시가 흔들리지 않게). 이름·예약번호·체크인·체크아웃·저장 시각을 그대로 옮기고, 날짜 칸이 없고 `dates`만 있던 더 예전 저장본도 첫 날짜·마지막 날짜를 살린다.
- 항공권·그 밖의 서류는 **그대로 남는다**. 옮긴 숙소는 예약 서류 목록에서 빠진다(같은 숙소가 두 곳에 보이지 않게).
- 주소는 예약 서류에 없던 값이라 비어 있고 사람이 채운다. 여행 id가 없어 **날짜가 겹치는 여행**에서 보이고(날짜도 없으면 모든 여행), 그 여행에서 한 번 고치면 그 여행 숙소가 된다.
- 옮길 것이 없으면 같은 객체를 그대로 돌려주므로 몇 번 열어도 결과가 같다. `StaysTest.migratesLodgingBookingsKeepingIds`가 본다.

## 4. 개인정보

- 숙소 이름·주소는 **암호화 보관함**에만. 가는 곳(잠금 없는 DataStore)에는 보여 주기에 필요한 이름·주소만 복사한다(인터넷·지문 없이 기사님께 보여 줘야 해서 — 예전 가는 곳과 같은 이유).
- 여행 장부(DataStore)에는 주소 글자가 아니라 `TripChecks.stayAddress`(있다/없다)만 적는다. `ChecklistTest.stayAddressSignalKeepsNoAddressText`가 저장 글자에 주소가 없는지 본다.
- `StayRecord.toString()`·`BookingFields.toString()`은 이름·주소를 찍지 않는다(있다/없다만). 로그·알림·Crashlytics·Firestore로 나가는 값 없음.
- 숙소를 보여 주는 화면(숙소 넣기·고치기)은 FLAG_SECURE. 예약 단계 카드는 한 여행 화면 안이라 기존 규칙을 따른다.
- 테스트·갤러리에 쓴 숙소 이름·주소·전화는 모두 **지어낸 값**이다.

## 6. 남은 것 / 운영자에게 물을 것

1. **좌표 입력 칸이 없다**: 모델·지도 링크는 좌표를 지원하지만 화면에서 적는 칸은 두지 않았다(시니어가 받아 적을 값이 아니라고 봤다). 지도에서 집어 오는 방법이 필요하면 다음 단계로.
2. **여행 없이 옮겨 온 숙소**: 여행이 하나도 없는데 예전 숙소 예약 서류만 있으면 그 숙소를 볼 화면이 없다(여행을 만들면 날짜가 맞는 여행에서 보인다). 설정 › 내 정보에도 묵는 곳 목록을 둘지 물어볼 것.
3. **숙소 종류 매핑**: 그 나라 사이트에 없는 종류(예: MDAC의 게스트하우스)는 비워 두고 사람이 고르게 했다. `게스트하우스 → 그 밖의 숙소`처럼 앱이 대신 골라 주길 원하는지 확인 필요.
4. **원어민 검수**: 이번에 바뀐 레시피 라벨은 없다(칸 이름·현지어는 그대로). 기존 검수 과제(QUESTIONS C10·C16·C17)는 그대로 남아 있다.
