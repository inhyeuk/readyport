# 여행 과정 길잡이 — 메뉴 구조 개편 (2026-10-03)

운영자 지적:

> "메뉴 구조가 여전히 조금 구분이 모호하고 디자인의 완성도가 낮은 상태야. 여행 일정(생각→일정 검토 및 정리→ 각종 예약→(반)자동 신청 등 처리→ ... → 출국/입국 → 여행 → 복귀) 등의 과정이 제대로 안내 되고 그 흐름으로 처리되면 좋겠는데 현재 메뉴 구조는 그렇지 않아."

규칙은 `DESIGN_SPEC_2026-10-01.md` **부록 H**, 제품 명세는 `PRD.md` **4.1·4.3·5.1·5.12·5.16**, 저장·호환은 `ARCHITECTURE.md` **10.4b**와 '구현 결정 기록(여행 과정 길잡이)'.

## 1. 무엇이 문제였나 (합의한 진단)

앱에 **묶는 방식이 둘** 있었고 서로 겹쳤다.

| 묶는 방식 | 어디에 | 무엇을 담았나 |
|---|---|---|
| 나라 중심 | 홈 → 나라 카드 → 입국·비자 / 여행 정보 / 쇼핑 | 그 나라의 사실 |
| 시간 중심 | 내 여행 탭 → 오늘 화면(6단계) → 내 여행 목록 → 체크리스트(한 달 전·일주일 전·3일 전…) | 그 여행의 할 일 |

- **같은 일에 길이 셋**이었다: 꼭 챙길 물건은 홈 카드·여행 준비 탭·체크리스트 항목에, 입국 카드는 나라 화면·여행 준비 탭·오늘 화면·체크리스트에, 귀국 전 확인은 홈·나라 쇼핑·쇼핑 리스트·오늘 화면에.
- **예약은 집이 없었다.** 예약 서류 가져오기는 `설정 › 내 정보` 안에만 있어서 여행 흐름 어디에서도 보이지 않았다.
- 체크리스트는 **언제**(한 달 전/일주일 전/3일 전)로 묶여 있는데, 사장님은 **무엇**(예약·신청·출국)으로 생각한다.

## 2. 고친 방식 — 두 축을 가른다

| 축 | 값 | 무엇을 정하는가 | 팩 필드 |
|---|---|---|---|
| **단계** (무엇을 하는 일) | 계획 · 예약 · 서류 · 짐 · 출국 · 입국 · 여행 중 · 복귀 | 묶기 · 단계 막대 · 지금 할 일 | `checklist[].stage` (새로) |
| **기한** (언제까지) | 한 달 전쯤 · 일주일 전 · 3일 전 · 출발하는 날 · 도착하면 · 여행 중 · 돌아오기 전 · 돌아와서 | 기한 날짜 · 늦음 · 챙길 일 알림 | `checklist[].phase` (예전 값 그대로) |

두 축은 **독립**이다. `짐` 단계 안에 기한이 `일주일 전`인 해외 결제 카드와 `3일 전`인 현지어 카드 미리 보기가 함께 있다.
**기한·늦음·알림 규칙은 2026-10-02와 한 글자도 다르지 않다** — 바뀐 것은 묶는 방식뿐이다.

## 3. 탭 (before → after)

```
[ before ]                               [ after ]
홈          — 나라 + 여행 준비 조각 4개    둘러보기  — 나라 고르기 + 여행 만들기 한 줄
내 여행      — 오늘 화면(6단계)            내 여행    — 여행 목록 → 한 여행 화면(8단계)
도움                                      도움       (그대로)
설정        — 내 정보 안에 예약 서류       설정       (내 정보는 그대로, 예약은 여행으로도)
```

- **둘러보기** = 여행을 만들기 전의 '생각' 단계. 사진 히어로 → (여행이 있으면) 내 여행 카드 → 나라 사진 카드 → (여행이 없으면) `여행 만들기` 카드 → 급할 때는 도움. 그것뿐이다.
  여행이 없을 때 `여행 만들기`가 나라 **아래**인 것은 첫 화면 예산 때문이다 — 나라 사진이 첫 화면에 보여야 한다(운영자 결정 9번, `HomeFirstScreenTest`).
- **내 여행** = 여행 줄기. 여행 목록 → **한 여행 화면**: 나라 사진 머리 → 8단계 막대 → 지금 할 일 → 알림 한 줄 → 단계 카드 여덟 → 내가 넣은 항목 → 급할 때는 도움 → 기기 안 저장 → 이 여행 지우기.

## 7. 예전 데이터는 어떻게 살아남나

1. **체크는 항목 id**(`booking` · `essential.payment` · `country.cash_declare` …)로 저장한다 — 묶음이 바뀌어도 그대로다. `JourneyStagesTest.checkStatesSurviveTheRegrouping`이 예전 팩/새 팩에서 같은 체크가 같은 수로 남는지 본다.
2. **예전 서명 팩**(`stage` 없음)은 앱이 `phase`에서 단계를 옮겨 온다: month→계획 · week→짐 · three_days→서류 · departure_day→출국 · arrival→입국 · during→여행 중 · before_return·back→복귀. 항목이 하나도 빠지지 않고 기한도 그대로다(`oldSignedIndexFallsBackToLegacyStages`).
   예전 색인에는 `예약`으로 가는 기한 이름이 없어서 그 단계에는 항목이 없다 — 그래서 화면은 **언제나 여덟 단계를 그린다**(단계마다 그 단계에서 하는 일이 있다). 예약 서류 넣어 두기는 그대로 닿는다.
3. **기한·알림**: `phase` 값과 기한 날짜 계산을 손대지 않았다. 늦음·급함·알림이 고르는 항목이 예전과 같은지 `dueDatesAreUnchangedByTheRegrouping`·`remindersAreIdenticalBeforeAndAfterTheRegrouping`이 본다.
4. **알림 차례**: 급함·늦음이 같은 항목들 사이의 차례가 목록 순서를 따르므로, 기한을 비교 기준에 더했다(`급한 것 → 늦은 것 → 기한이 이른 것`). 알리는 **항목과 때는 그대로**이고 차례만 묶음과 상관없이 고정된다.
5. **여행 저장본**(`Trip`)은 바뀌지 않았다. 딥링크(`readyport.open_checklist` → `TripChecklistRoute(여행 id)`)도 이름·동작 그대로다.

## 8. 팩 데이터

- 색인 `checklist[]` 29줄 + 나라 팩 체크리스트 15줄에 `stage`를 넣었다. 스키마에 `stage`(선택, 예전 팩 호환) + `build_packs.py`가 **새로 쓰는 팩에는 요구**한다.
- 버전: 색인 `2026.10.03-2`, 아홉 나라 팩 모두 `2026.10.03-2`. 서명 다시(`--kid rp-2026-1`). 배포(Hosting·RC 버전 포인터)는 하지 않았다.

## 9. 디자인

- 단계 막대는 나라 화면 그림 메뉴(부록 E.6)와 **같은 그림 언어**다: 그라데이션 패널 + 일러스트, 고른 칸은 떠오름 + 짙은 그라데이션 + 가운데 Accent 알약 막대.
- 단계 그림 일곱 장을 새로 그렸다(64 격자·2.4 둥근 선·진한 외곽선 + 주색 + 옅은 중간색 + 금색 포인트, 외부 자산 없음): 계획(달력 + 금색으로 동그라미 친 날짜) · 예약(항공권 두 장 + 금색 절취 쪽) · 짐(여행 가방 + 금색 이름표) · 출국(이륙 + 활주로 + 구름) · 입국(터미널 + 내려오는 비행기) · 여행 중(사진기) · 복귀(집 + 돌아오는 비행기). **서류**는 입국·비자와 같은 일이라 기존 `Illus.Entry`(여권 + 입국 도장)를 그대로 쓴다.
- 색 차례 **파랑 · 청록 · 파랑 · 보라 | 파랑 · 청록 · 주황 · 보라** — 이웃이 같은 색이 되지 않게.
- 주 버튼(채운 버튼)은 화면에 하나(맨 위 `지금 할 일`). 단계 안 버튼은 모두 테두리 보조 버튼(`도착했어요` 포함).

## 10. 문구

- 새 문구는 `res/values/strings_journey.xml`에만(단계 이름 여덟·단계 설명 여덟·단계 막대 이름·예약 서류·둘러보기 CTA·나라 화면 `이 여행` 띠 — 27줄).
- 화면이 사라지면서 **더는 쓰지 않는 문구 67줄**을 지웠다(`오늘` 화면·여행 준비 탭·둘러보기 여행 준비 카드·시간 묶음 이름 `한 달 전쯤`~`돌아와서`). lint `UnusedResources`가 가리킨 것만 지웠고, 운영자 결정 16번의 `rankings_*`(인기 순위 문구)는 그대로 둔다.

## 11. 남은 것 · 운영자에게 물을 것

1. **둘러보기에서 '귀국 전 확인' 요약을 뺐다.** 운영자 결정 10은 '전체는 내 여행 복귀 단계에만, 홈·나라 쇼핑·쇼핑 리스트는 한 줄 요약'이었다. 홈이 둘러보기(여행 전 단계)가 되면서 그 자리에 둘 이유가 없어졌다 — 나라 쇼핑·쇼핑 리스트의 한 줄 요약은 그대로다. **되돌릴지 확인 필요.**
2. **여행 준비 탭 화면을 없앴다.** 입국 서류를 나라와 상관없이 한 목록으로 보던 화면이다. 여러 나라를 한꺼번에 준비하는 사람에게 쓸모가 있었는지 확인 필요.
3. **둘러보기에 여행 영상 바로가기를 따로 두지 않았다.** 영상은 나라 화면 '여행 정보' 안에 있다(길은 하나). 둘러보기에서 바로 가고 싶은지 확인 필요.
4. 단계 이름(`계획 · 예약 · 서류 · 짐 · 출국 · 입국 · 여행 중 · 복귀`)이 사장님 말과 같은지 — 특히 `서류`(= 비자·입국 카드 신청)와 `복귀`.
5. 배포는 하지 않았다: 팩 Hosting·Remote Config 버전 포인터는 main 머지 뒤.
