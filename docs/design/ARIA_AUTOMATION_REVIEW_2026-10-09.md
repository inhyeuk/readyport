# ARIA 자동화 검토 — ① 관광지 주간 갱신 ② 게시판 여행 계획 설계 요청 (2026-10-09)

> 사장님 요청(2026-10-09): ① ARIA로 매주 1회 나라별 주요 관광지의 바뀐 내용과 관광객 만족도를 자동 갱신.
> ② 이용자가 여행 목적·동행자(가족 수·노인·성별·연령·신체 조건)·기간·예산을 넣고 계획을 요청하면,
> 에이전트가 1시간마다 확인 → Claude로 설계 → PDF → 앱으로 제공. 1인당 주 2회 제한.

## 현재 바탕
- `ops/aria/`(이 저장소)에 ARIA용 운영 모듈이 이미 있다: 감지기(공지·양식 구조 해시), `runners/claude_headless.py`(claude -p 래퍼, 하루 상한),
  `approvals/telegram_cmd.py`(텔레그램 승인), 지문 저장소(같은 변경 1회만). 원칙 = 감지는 결정적으로, 판단은 Claude, **게시는 사람 승인**.
- 단, **ARIA 본체와의 연결(스케줄 등록·서비스 계정)은 아직 안 됐다**(README "연결은 운영자가 한다", aria-watchdog 워크플로 꺼짐).
- 관광지 데이터는 서명된 파일 + 공식 출처 인용 기계 대조(`tools/attractions/build_attractions.py`)로만 바뀐다. 나라 공개는 사장님 캡처 승인(D22).

## ① 관광지 주간 갱신 — **가능. 단 '만족도'는 출처 선택이 필요**

### 바뀐 내용 감지·반영 (권장 구조)
1. **매주 1회(예: 월 06:00) ARIA 감지**: 나라별 관광지의 공식 출처 URL(이미 `sources`·evidence에 있음)을 GET → 본문 해시 비교. 바뀐 곳만 증거 스냅샷 저장. (LLM 없음, 같은 변경은 1회만)
2. 바뀐 곳만 **Claude 헤드리스**가 새 원문에서 사실·인용을 다시 뽑아 초안(`packs/drafts/<CC>`)을 고치고 `build_attractions.py check`(인용 기계 대조·글 베끼기 검사)를 통과시킨다.
3. **텔레그램으로 요약 + 화면 캡처 승인 요청** → 승인하면 서명 → PR → 머지 → 배포. 거절하면 버린다.
4. 휴관·공사·폐쇄처럼 **안전 쪽 변경**(예: '임시 휴관')은 승인 전에도 상세에 '공식 안내가 바뀌었어요 — 확인 중' 띠만 켤 수 있게(기존 kill-switch 원칙과 같음).
- 비용: 감지는 무료(HTTP GET). Claude는 바뀐 곳만, 하루 상한 유지. 9개국 수백 곳이어도 주 1회 GET은 사이트당 1회 수준이라 부담이 작다(요청 간격 3초, robots 준수, 봇 차단이면 우회 없이 '사람 확인').

### '관광객 만족도'
| 방법 | 가능 여부 | 메모 |
|---|---|---|
| 구글 별점을 매주 받아 앱 파일에 저장 | **불가(약관)** | Google Maps Platform 약관상 Places 내용은 저장(캐시) 예외가 place ID·좌표(30일)뿐 — 별점·리뷰를 주간으로 모아 두는 것은 허용되지 않는 것으로 보는 게 안전 |
| 트립어드바이저·네이버 등 리뷰 수집 | **불가** | 크롤링 금지·약관(네이버 크롤링은 이전에 기각한 원안과 같은 문제) |
| **구글 별점을 상세 화면에서 그때그때 표시** | 가능(유료) | 상세를 열 때 Places API(New)로 조회, 'Google 제공' 표시 필수, 저장 안 함. 지도 키와 같은 결제 계정. 열람 수에 비례해 비용 |
| **레디포트 이용자 만족도(자체 평점)** | 가능(무료) | '다녀왔어요' + 별점·한 줄(만 19세 이상, 게시판 계정). 처음엔 표본이 적어 '평가 N명 미만이면 숨김'. 주간 집계는 ARIA가 Firestore에서 계산해 숫자만 반영 |
| 위키백과 조회수 등 '인기' 지표 | 가능(무료) | 만족도가 아니라 관심도. 이미 순서(D11)에 쓰고 있음 |

## ② 게시판 여행 계획 설계 요청 — **가능. 단 4가지를 바꿔야 안전하다**

### 꼭 바꿔야 할 점
1. **공개 게시판에 쓰면 안 된다.** 가족 구성·나이·장애·건강 같은 정보는 공개 글이 되면 그대로 노출된다. 장애·건강은 「개인정보 보호법」 제23조 **민감정보**(별도 동의 필요).
   → 게시판 탭 안에 **비공개 '여행 계획 요청' 양식**을 두고, 요청과 결과는 **본인과 운영자만** 볼 수 있게(Firestore 규칙).
   신체 조건은 진단명 자유 서술 대신 **선택형**(예: '오래 걷기 어려워요', '휠체어를 써요', '계단이 어려워요', '어린아이와 함께')으로 최소화하고 **별도 동의**를 받는다.
2. **Claude 구독 계정으로는 안 된다.** Anthropic 약관상 Pro·Max 구독의 로그인은 Claude Code·Claude.ai 전용이고, 다른 사람에게 제공하는 서비스의 엔진으로 쓰려면 **API 키(종량제)** 가 필요하다.
   → 사장님이 Anthropic Console에서 API 키 발급·결제 등록(건당 대략 수십~수백 원 수준, 계획 길이에 따라) — ARIA가 이 키로 호출.
3. **PDF는 서버에 올리지 않고 기기에서 만든다.** Firebase Storage는 Blaze(종량제) 전용이 됐다. 결과를 구조화된 글(일정표 JSON)로 Firestore 비공개 문서에 넣고, 앱이 보여 주면서 'PDF로 저장'을 누르면 **휴대폰 안에서 PDF를 만든다**(Spark 그대로).
4. **AI가 만든 결과라는 표시**와 '공식 안내로 다시 확인' 고지. (2026-01-22 시행 인공지능기본법의 생성형 AI 고지·표시 의무 대상인지 변호사 확인 목록에 추가)

### 흐름
앱(요청 양식, 만 19세 이상·게시판 계정) → Firestore `plan_requests/{id}`(본인·운영자만) →
ARIA **1시간마다** 새 요청 확인 → 제한 확인(1인 주 2회) → Claude API로 설계(관광지 팩·체크리스트·숙소 지역 정보를 근거로, 지어낸 영업시간·가격 금지) →
결과 `plan_results/{id}` → 앱이 다음 열 때(또는 하루 1회 확인 작업) '여행 계획이 도착했어요' 알림 → 화면 + 기기에서 PDF.
- **1인 주 2회**: Firestore 규칙(요청 문서 생성 시 최근 7일 개수 확인)과 ARIA 쪽 이중 확인. 익명 계정이라 앱을 지우고 다시 깔면 새 계정이 되는 한계는 남는다.
- **보관**: 결과 전달 후 30일 지나면 요청·결과 자동 삭제(ARIA 매일 정리). 처리방침·데이터 보안 양식에 '민감정보(선택)'·'AI 처리 위탁(Anthropic, 미국)' 추가.
- **품질 관리**: 처음 몇 주는 결과를 보내기 전에 텔레그램으로 사장님 확인(승인 후 전송) → 안정되면 자동 전송으로.
