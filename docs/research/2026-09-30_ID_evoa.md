# 인도네시아 전자도착비자(e-VOA) 자동 입력 가능성 조사 (2026-09-30)

> 조사 방법: 공식 출처(인도네시아 이민국 imigrasi.go.id·evisa.imigrasi.go.id·allindonesia.imigrasi.go.id, 외교부 0404.go.kr, 주인도네시아 대사관)만 GET으로 읽음. 가입·로그인·입력·제출·결제 없음. 캡차는 건드리지 않음(로그인 화면 HTML에 캡차가 있다는 것만 확인).
> 확인일: 2026-09-30 (한국 시각). 확인 못 한 값은 `[확인 필요]`.
> 레시피·팩 파일은 고치지 않았다. 아래 "레시피 초안 표"는 참고용이다.

## 한 줄 결론

- **e-VOA는 이제 따로 채울 양식이 없다.** 이민국 누리집의 "E-Visa on Arrival" 버튼이 All Indonesia로 넘어가고, All Indonesia에서 **도착 카드를 낸 뒤 요약 화면의 "도착 비자(VOA) 신청" 버튼 → 이메일 확인 창 → 결제 화면**으로 끝난다. 비자에 필요한 정보는 도착 카드에 적은 내용을 그대로 쓴다.
- 그래서 앱이 할 일은 **이미 있는 `ID_ALL_INDONESIA` 레시피로 도착 카드를 채우는 것까지**다. VOA 신청 버튼·결제는 사람이 직접 누르고 카드 번호를 넣는다(앱은 안내만).
- 로그인: All Indonesia 현재 코드에서 로그인·가입 화면은 꺼져 있다(주소로 가도 첫 화면으로 돌려보냄). 계정 없이 된다.
- 권장: **"도착 카드는 자동 입력 + VOA 신청·결제는 안내만"** (새 레시피 불필요, 기존 레시피에 안내 문구·체크포인트만 추가 검토).

## 2. 신청 흐름

### 2-1. 지금 쓰이는 길: All Indonesia 안에서 신청

All Indonesia 공개 앱 코드(`/assets/index-C4N2qKCA.js`, 약 6.0MB, 2026-09-30 받음)에서 확인:

1. 도착 카드(개인 정보 → 여행 정보 → 교통·주소 → 신고)를 낸다. **마지막 신고 제출 때 그림 글자 캡차**가 있다(`captchaCode`·`captchaToken`, API `ARR_SUB_DECLARATION_CAPTCHA_V2_SUBMIT`). Google reCAPTCHA·hCaptcha·Turnstile 코드는 없다(`hCaptcha` 검색 결과는 `submissionRetrieveSearchCaptcha`의 글자 일부일 뿐).
2. 요약 화면에 "Arrival Card is not a visa" 안내와 함께, 서버가 `isVoa = "Y"`로 주면 초록 버튼 **"Apply for Visa On Arrival (VOA)"**(한국어 화면: "도착 비자(VOA) 신청")가 나온다. 안내 문구: "You are Visa On Arrival (VOA) subject, Please apply for VOA after successfully submitting your arrival card."
3. 버튼 → 확인 창("Confirm Your Visa On Arrival Applyment", 도착 카드에 적은 이메일을 보여 줌) → "Apply(제출)".
4. 앱이 `POST /submission/apply-visa`에 `{deviceLang, tokenApplyVisa, visaType:"VOA"}`만 보낸다. **입력 칸이 더 없다.** 응답의 `paymentUrl`로 페이지가 넘어간다(결제 페이지 주소는 서버가 줌 → 어느 결제사인지 `[확인 필요]`).
5. 결제 뒤 `?flow=payment_voa`로 돌아와 성공/실패 창. 성공하면 "e-VOA는 등록한 이메일로 보냄", 요약 화면에 "Download e-VOA" 버튼. 결제 대기 중이면 "결제 상태 확인" 버튼.

로그인·가입:
- 코드에 `/login`, `/register-form/foreigner` 등 화면이 있지만 **라우터가 모두 첫 화면(`/`)으로 돌려보낸다**(`loader:()=>_e("/")`). 도착 카드 화면(`/arrival-card-submission/...`)은 로그인 조건이 없다(`loader:()=>null`, 진행 단계만 확인).
- 즉 현재 코드 기준 **계정·로그인 필요 없음**. (서버 쪽 정책이 바뀌면 달라질 수 있어 실기기 확인 권장 `[확인 필요]`)

### 2-2. 옛 길: evisa.imigrasi.go.id 비자 고르기 → 로그인

- `https://evisa.imigrasi.go.id/web/visa-selection`: 국적(`#selectCountry`, "REPUBLIC OF KOREA" 있음) → 목적 → 비자 종류 → 체류 기간을 고르는 화면. 목록은 `POST /web/visa-selection/data`로 받아서, **GET만 쓰는 규칙상 e-VOA가 여기 아직 있는지는 확인 못 함 `[확인 필요]`.**
- 코드상 비자 종류에 `is_login`이 켜져 있으면 `/front/application_add/...`(로그인 필요)로, 아니면 `/web/application_add/...`로 간다.
- 로그인 화면 `https://evisa.imigrasi.go.id/front/login?menu-token=...`: 아이디(`#username`, name `_username`)·비밀번호(`#password`) + **Google reCAPTCHA v2**(`g-recaptcha`, 제출 전에 `grecaptcha.getResponse()` 검사). 가입 화면 `https://evisa.imigrasi.go.id/front/register`(외국인/보증인 선택).
- 이 길은 계정·비밀번호·reCAPTCHA가 걸려 있어 앱 자동 입력 대상이 아니다(작업 규칙: 계정 만들기·로그인·캡차 대신 풀기 금지). **안내만.**

## 4. 입력 칸 선택자 (공개 코드에서 확인)

e-VOA 자체는 입력 칸이 없다. 아래는 e-VOA에 쓰이는 정보를 받는 **All Indonesia 도착 카드** 칸이다. 기존 레시피가 본 코드는 `index-D5TNio3l`, 오늘 받은 코드는 **`index-C4N2qKCA`로 바뀜**. 기존 레시피의 id 16개는 새 코드에도 모두 있다(접두 일치 `[id^="..."]` 그대로 유효). 실제 id는 `std_arrival_date_foreigner_individual`처럼 뒤가 붙어 있다.

컴포넌트 구분(코드 기준): `js` = 글자 입력칸, `AA` = 달력, `Dm` = 검색형 선택 목록, `hA` = 라디오, `qk` = 호텔 검색 목록.

## 6. 권장

1. **새 e-VOA 레시피는 만들지 않는다.** 채울 칸이 없고, 남은 단계는 "신청 버튼 → 이메일 확인 → 카드 결제"라 전부 사람이 해야 하는 일이다.
2. 기존 `ID_ALL_INDONESIA` 레시피를 쓸 때(운영자 승인 후 별도 작업):
   - `site_version_seen`을 `index-C4N2qKCA`로 갱신 검토(id는 그대로 유효).
   - 추가 후보: `spi_country_or_place_of_birth`, `smta_place_of_arrival_air_foreigner`(둘 다 assist).
   - 마지막 제출 전 캡차 체크포인트(`kind: "captcha"`) 추가 검토 — 신고 제출에 그림 글자 캡차가 있음.
   - 요약 화면 안내 문구: "초록색 '도착 비자(VOA) 신청' 버튼을 직접 누르고, 적은 이메일이 맞는지 확인한 뒤 카드로 IDR 500,000을 내세요."
3. 팩 문구(`packs/src/ID/pack.json`)의 "미리 공식 사이트(evisa.imigrasi.go.id)에서" 는 사실이지만, 실제 입구가 All Indonesia 도착 카드 뒤로 옮겨졌다는 점을 덧붙일지 운영자 판단 필요(정책 의미 변경이라 사람 승인).
4. 유사 사이트 경고(대사관 2026-09-21)를 안내에 넣고, WebView 허용 주소를 `*.imigrasi.go.id`로 한정.

## 남은 `[확인 필요]`

- evisa.imigrasi.go.id의 비자 고르기에 e-VOA가 아직 남아 있는지, 로그인이 필요한지(POST 목록이라 못 봄).
- All Indonesia VOA 결제 화면의 주소(결제사)와 서비스 요금 유무·금액.
- 도착 카드에서 "비자 보유?"에 "아니요"를 골라야 VOA 신청 버튼이 뜨는지(서버가 `isVoa` 결정). 실기기에서 운영자가 본인 여행 때 화면 확인 권장.
- 이름 칸(`spi_full_name`)을 text로 올려도 되는지(코드상 글자칸이지만 기존 레시피는 assist).
