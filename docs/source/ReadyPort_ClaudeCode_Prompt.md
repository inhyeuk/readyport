# 레디포트(ReadyPort) 개발 지시서 — Claude Code용

> 작성 기준일: 2026-09-28
> 이 문서는 앱 개발 전체를 Claude Code에 맡기고, 출시 후 운영(정책 변경 반영)은 운영자의 로컬 에이전트 **ARIA**가 관리하도록 설계한 완성본 지시서입니다.
> `[재확인]` 표시는 작성 시점에 조사한 사실이지만 바뀔 수 있는 항목입니다. 구현 전에 공식 출처로 다시 확인하세요.
> `[확인 필요]` 표시는 아직 확정되지 않은 값입니다. 추측으로 채우지 말고 운영자에게 질문하세요.

## 0. Claude Code에게 — 작업 시작 방법

당신은 이 프로젝트의 리드 Android 엔지니어입니다. 아래 순서로 시작하세요.

1. 이 문서를 저장소에 나눠 저장합니다.
   - `CLAUDE.md` ← 이 문서의 **15장(작업 규칙)** 전체와 1장 요약
   - `docs/PRD.md` ← 1~8장, 11장
   - `docs/ARCHITECTURE.md` ← 9~10장
   - `docs/ARIA_OPS.md` ← 12장
   - `docs/ROADMAP.md` ← 13~14장
2. 구현 전에 **질문 목록**을 먼저 만들어 운영자에게 보여 주세요. `[확인 필요]` 항목, 라이브러리 버전, 계정·키 발급처럼 사람이 해야 하는 일을 모읍니다.
3. 13장 마일스톤 순서대로 진행하고, 마일스톤마다 "완료 기준" 충족 여부를 보고한 뒤 다음으로 넘어갑니다.
4. 첨부된 `readyport_icon_assets.zip`의 `res/` 폴더를 `app/src/main/res/`에 그대로 복사해 앱 아이콘으로 씁니다(8.4절).

## 1. 제품 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | 레디포트 (ReadyPort) |
| 플랫폼 | Android (Kotlin, Jetpack Compose) |
| 가격 | 무료. 광고 없음. 수익은 제휴 링크(11.2절)로만 |
| 한 줄 정의 | 해외여행 준비부터 귀국까지 함께하는 '여행 필수품' 앱. 입국 사전신고를 앱이 대신 채워 주고, 사용자는 확인과 최종 제출만 한다 |
| 핵심 대상 | 해외여행 경험이 없는 중학생, 중년 이상. 누구나 설명 없이 쓸 수 있어야 한다 |
| 핵심 약속 | ① 여권 등 개인정보는 폰 밖으로 나가지 않는다 ② 인터넷이 없어도 핵심 기능이 동작한다 ③ 공식 출처와 최종 확인일을 항상 보여준다 |
| 서버 | Firebase 무료 요금제(Spark)만 사용. 서버 로직 없음 |
| 운영 | 정책·양식·콘텐츠 변경 감지와 반영은 ARIA(운영자 PC의 자율 에이전트)가 담당 |

### 1.1 서비스 원칙 (전문가 검토로 확정)

1. 한 화면에는 할 일 하나. 다음에 누를 버튼이 항상 분명해야 한다.
2. 쉬운 말. 중학교 1학년 수준 어휘를 쓰고, 전문 용어에는 풀이를 붙인다.
3. 앱이 채우고 사람은 확인한다. 사용자는 승인과 최종 제출만 한다.
4. 인터넷이 없어도 동작한다. 찜한 여행지와 도움 탭은 항상 오프라인.
5. 현지어는 '읽는 용'이 아니라 '보여주고 들려주는 용'으로 크게 표시한다.
6. 모든 정책 정보에 공식 출처와 최종 확인일을 붙인다.
7. 개인정보는 기기 안에만 둔다.

## 2. 서비스 범위 — 국가·양식

### 2.1 사전신고 유형별 지원 수준

| 유형 | 대상 (2026-09 기준 `[재확인]`) | 지원 수준 | 단계 |
|---|---|---|---|
| 무료 전자 입국카드 (웹) | 태국 TDAC, 말레이시아 MDAC, 싱가포르 SG Arrival Card, 인도네시아 All Indonesia(입국·세관·검역 통합), 일본 Visit Japan Web | 자동 입력 + 사용자 최종 제출 | **MVP** |
| 유료 전자여행허가 (웹 경로 있음) | 캐나다 eTA, 뉴질랜드 NZeTA, 영국 ETA 웹 신청 | 자동 입력. 결제·얼굴 사진·배경 질문은 사용자 | 2차 |
| 공식 앱 전용 (칩 판독·실시간 얼굴 인증) | 호주 ETA, 영국 ETA 앱, 미국 ESTA | 자동화하지 않음. 준비물 체크리스트, 공식 앱 연결, 값 복사 버튼만 | 2차 |
| 시행 예정 | EU ETIAS | 감시만. 시행 확정 시 추가 | 관망 |

참고 사실 `[재확인]`:
- 태국 TDAC는 도착 72시간 이내에만 제출 가능, 무료.
- 싱가포르 SG Arrival Card는 도착 3일 이내 제출.
- 미국 CBP는 ESTA 웹사이트 신규 신청을 폐지하고 모바일 앱으로 단일화하는 안을 제시했다(2025-12). 대리 신청 시에도 신청자 본인 얼굴 사진이 필요하다.
- 영국 ETA는 2026-04-08부터 £20. 대리 신청 가능하나 "다른 사이트·앱을 통해도 결정이 빨라지지 않는다"고 공식 안내.
- EU ETIAS는 2026년 말 목표가 공식 사이트에서 삭제되었고 2027년 연기 가능성이 보도됨.
- 2026년 봄 인도·베트남도 디지털 입국카드를 도입. 양식 수는 계속 늘어나는 추세.

### 2.2 절대 자동화하지 않는 것 (사람 확인 지점)

- 캡차(보안 문자). **우회 시도 금지**.
- 이메일·문자 OTP
- 셀피·실시간 얼굴 인증
- 결제
- 서약, 세관·건강·범죄 이력 질문. 앱이 추정하거나 기본값으로 채우지 않는다. 그림 + 예/아니오로 사용자가 직접 답하게 한다.
- 최종 제출 버튼

## 3. 대상 사용자와 사용 모드

### 3.1 페르소나

| 페르소나 | 특징 | 설계 반영 |
|---|---|---|
| 58세 부부, 첫 해외여행 | 무엇을 모르는지 모름, 작은 글씨·스와이프 어려움 | 쉬운 모드, '지금 할 일' 1개, 음성 안내 |
| 중학생 자녀를 둔 4인 가족 | 보호자가 서류를 한꺼번에 관리 | 가족 모드 |
| 중학생 (첫 해외여행) | '승인', '입국신고서' 같은 말을 모름 | 쉬운 말 사전, 버튼 문구 |
| 저시력 70대 | 큰 글씨, 높은 대비 필요 | 글자 확대 대응, 명도 대비 |
| 배낭여행 경험자 | 빠르게 쓰고 싶음 | 기본 모드 |

### 3.2 쉬운 모드
- 첫 실행 때 "해외여행이 처음이세요?"라고 묻고, 예라고 하면 기본으로 켠다. 설정에서 끄고 켤 수 있다.
- 글자 18~28sp, 버튼 높이 56dp 이상, 한 화면 한 가지 주요 동작.
- 스와이프 제스처 금지. 모든 동작은 버튼으로.
- 모든 화면에 '처음으로' 버튼.
- 음성 안내: Android TextToSpeech(기기 내장) 사용.

### 3.3 가족 모드
- 보호자 폰이 대표로 가족 전체의 여권·프로필·QR을 관리한다.
- 자녀 폰에는 자기 QR과 도움 탭만 단순하게 보여준다.
- 자녀 QR을 자녀 폰으로 옮길 때는 서버를 거치지 않고 기기끼리 직접 공유(QR 스캔 또는 시스템 공유)한다.
- 동행자 등록 시 "본인 또는 보호자가 동의했나요?" 확인 문구를 표시한다.

### 3.4 쉬운 말 사전 (UI 문구 규칙)

| 원래 용어 | 앱 문구 |
|---|---|
| 전자여행허가(ETA) | 미리 받는 입국 허락 |
| 입국신고서 | 도착 전에 내는 입국 카드 |
| 세관 | 가방 속 물건을 확인하는 곳 |
| 체크인 | 비행기 표 받고 짐 맡기기 |
| 승인 | "맞아요, 입력해 주세요" |

`app/src/main/res/values/strings.xml`에 원래 용어를 쓰지 말고, 쉬운 말 문구를 기본으로 한다. 전문 용어가 꼭 필요하면 괄호로 병기한다.

## 4. 정보 구조 (IA)

### 4.1 하단 탭 5개

| 탭 | 역할 | 주요 화면 |
|---|---|---|
| 오늘 | 여행 단계에 따라 바뀌는 첫 화면 | 준비 중: D-day 할 일 / 여행 중: 다음 일정 + '여기로 가기' / 귀국 후: 정리 |
| 준비 | 서류와 준비물 | 입국 서류(3개 국어 확인 → 자동 입력 → 제출), 꼭 챙길 물건(구매 링크), 앱 준비 체크리스트, 예약 서류 |
| 여행지 | 탐색·찜·현지 정보 | 요즘 인기 여행지, 찜한 여행지(오프라인 저장), 국가·도시 가이드(기본·계절·교통·결제·음식·여행지·안전·쇼핑), 이동하기 |
| 지갑 | 내 서류 | 여권, 여행자 프로필, 동행자, 예약 서류, 발급 문서(QR·확인서), 보안 설정 |
| 도움 | 위기 대응 (항상 오프라인) | 현지어 문장 카드, 긴급 전화, 대사관, 여권 분실·아플 때 할 일 순서 |

- 설정은 '오늘' 화면 오른쪽 위 톱니 버튼으로 들어간다. (별도 '더보기' 탭 없음)
- 설정 안: 쉬운 모드, 가족 모드, 오프라인 팩 관리, 알림(국가별 정책 변경 구독), 개인정보 안내(기기 내 처리·전체 삭제), 출처·면책(정부 비제휴 고지·라이선스), 오류 제보, 앱 정보·오픈소스, 여행사 소개(2차).
- 도움 탭 아이콘·라벨은 다른 탭과 구분되는 따뜻한 색(#A8431A)으로 항상 표시한다.

### 4.2 여행 단계 (8단계) — '오늘' 화면이 단계에 맞춰 자동 전환

| 단계 | 시점 | 앱이 알아서 하는 일 | 사용자가 하는 일 |
|---|---|---|---|
| ① 꿈꾸기 | 언제든 | 찜한 여행지를 Wi-Fi에서 자동 저장 | 찜하기 |
| ② 여행 만들기 | D-60 전후 | 필요한 서류 판정, 준비 일정 자동 생성 | 목적지·날짜·동행자 입력 |
| ③ 준비 | D-30~D-1 | 여권 유효기간 점검, 제출 가능일 알림, 꼭 챙길 물건 목록, 교통 앱 설치·가입 안내 | 여권·예약 서류 촬영, 앱 설치 |
| ④ 사전 신고 | 제출 가능일 | 3개 국어 확인 화면 준비, 공식 사이트 자동 입력 | 확인, 보안 문자, 최종 제출 |
| ⑤ 출국 | 당일 | 공항 가는 법, 체크인·보안검색 순서 카드 | 순서대로 따라가기 |
| ⑥ 도착 | 현지 도착 | 시간대 변경 감지 → 도착 모드: 입국심사 → 짐 → 유심 → 환전 → 숙소 이동 순서 카드, 입국 QR 즉시 표시 | QR 보여주기 |
| ⑦ 여행 중 | 매일 | 다음 일정, 이동 앱 연결, 현지어 카드, 오프라인 가이드 | '여기로 가기' |
| ⑧ 귀국·정리 | 귀국 후 | 한국 입국 안내, 쇼핑 목록 반입 확인, 여권 정보 파기 예고(미루기 가능), 경비 정리 | 파기 확인 |

- 도착 감지는 위치 권한 없이 `ACTION_TIMEZONE_CHANGED` + 여행 일정으로 판단한다.
- 파기 전에는 "사진·영수증은 남고 여권 정보만 지워요"라고 설명하고 '미루기' 버튼을 둔다.

## 5. 화면 명세 (와이어프레임 기준)

공통: 배경 #F4F5F7, 카드 흰색, 모서리 14~20dp. 정책·정보 카드 하단에 `출처 [기관] · 최종 확인 YYYY.MM.DD`. 대기 중 값은 `[ ]` 자리표시로 개발하고 실제 데이터로 교체.

### 5.1 오늘 (여행 중 상태)
- 맨 위: 오프라인일 때 남색 배너 "인터넷 없음 · 저장해 둔 정보로 보여 드려요".
- 헤더: "방콕 여행 2일째" / 큰 제목 "오늘 할 일" / 설정 버튼.
- 여행 단계 표시줄 6칸: 준비·출국·도착·여행 중·귀국·정리.
- 파란 큰 카드: 다음 일정(시간, 제목, 주의사항) + 흰 버튼 "여기로 가기" → 이동하기.
- 2×2 큰 버튼: 숙소로 돌아가기(→이동하기), 현지어 카드(→도움), 입국 QR 보기(→입국 시 제시), 오늘 쓴 돈 적기.

### 5.2 준비 › 입국카드 3개 국어 확인
- 제목 "태국 입국카드 확인", 설명 "앱이 서류를 보고 채웠어요. 맞는지 한 번만 확인해 주세요."
- 오른쪽 위 '현지어 크게' 토글.
- **서류에서 가져온 값 묶음 카드**: 행마다 왼쪽에 한글 라벨(크게) + `English · 현지어` 라벨(작게), 오른쪽에 값 + 출처 칩(여권에서/항공권에서/예약 확인서에서).
  - 예: 성(영문) · Family name · นามสกุล / 이름(영문) · First name · ชื่อ / 도착 날짜 · Date of arrival · วันที่เดินทางมาถึง
- **직접 골라 주세요 카드**(주황 테두리): 여행 목적 · Purpose of travel · วัตถุประสงค์การเดินทาง / 선택지 "관광 · Tourism · ท่องเที่ยว", "출장 · Business · ธุรกิจ".
- 안내: "확인하면 앱이 공식 사이트에 넣어 드려요. 보안 문자와 마지막 '제출'은 직접 눌러 주세요."
- 하단: 주 버튼 "맞아요, 입력해 주세요" → 자동 입력 / 보조 "고칠 곳이 있어요".
- 현지어 라벨은 국가 팩에서 가져온다. 번역은 원어민 검수 후 반영(14장).

### 5.3 준비 › 자동 입력 (WebView)
- 상단: '공식 사이트에 연결됨 · [공식 도메인]' + 자물쇠.
- 단계 표시(예: 개인정보 · 여행정보 · 숙소 · 확인·제출).
- 공식 사이트 WebView. 앱이 채운 칸은 파란 배경, 직접 확인할 칸은 주황 배경으로 강조.
- 공식 사이트 칸 옆에 **한글 말풍선 오버레이**.
- 주황 배너 "직접 확인 필요"(캡차·선택 항목·최종 제출).
- 입력값 대조 카드: 원본 서류 값 ↔ 입력된 값 ✓.
- 하단: '이 단계 다시 채우기' / '다음 단계 채우기', 오른쪽 위 '수동 모드'.

### 5.4 입국 시 제시
- 여행자 전환(본인 / 동행자).
- 양식 이름, '제출 완료' 태그, QR 크게, 확인번호, 이름(가림)·도착일·항공편·여권번호(가림).

- 홈 화면 위젯 제공.

### 5.5 지갑 / 여권 등록
- 지갑: 생체 인증 잠금 표시, 여권 카드(남색, 이름·번호 가림, 만료, 'MRZ 확인 완료', 'NFC 검증'(2차)), 여행자 프로필, 동행자, 여행별 서류(숙소·항공·발급 문서), '여행 종료 후 자동 파기' 스위치, "모든 서류는 이 기기 안에만 암호화해 저장합니다".
- 여권 등록: 단계(촬영 → 칩 확인(선택) → 값 확인), 촬영 화면(MRZ 가이드), "촬영 이미지는 기기 안에서만 처리하고, 값을 추출한 직후 삭제합니다", 추출 값 표(체크디지트 통과 태그), 'NFC 칩으로 한 번 더 확인', '확인하고 저장'.

### 5.6 여행지 › 요즘 인기 여행지
- 제목 + "한국 출발 여객·검색 추이로 매주 갱신".
- 필터 칩: 전체 · 비자 없이 · 비행 5시간 이내 · 이달에 좋은 곳 · 가족 여행.
- 순위 목록: 순위, 도시·국가, 태그(비자 없음 · 비행 시간 · 검색 급상승), 변동(▲▼–, NEW), 찜 하트.
- '순위는 이렇게 정해요' 설명 화면 연결, 기준 시점 표시("기준: 2026년 8월 여객 · 9월 4주 검색").

### 5.7 여행지 › 찜한 여행지 (오프라인 저장)
- 여행지 검색 버튼.
- 찜 카드: 도시·국가·여행 월, 상태 칩(저장 완료 / Wi-Fi 되면 받을게요 / 받는 중 %), 최종 업데이트·용량, '가이드 열기'.

## 6. 입국 서류 자동 처리 흐름

1. 제출 가능일 알림: "태국 입국카드를 낼 수 있어요". (로컬 알림, WorkManager)
2. 3개 국어 확인 화면(5.2):
   - 서류에서 온 값 → **묶어서 1번 확인**
   - 추정값·선택값(목적 등) → **개별 선택**
   - 세관·건강 질문 → **그림 + 예/아니오로 직접 답변**
3. "맞아요, 입력해 주세요" → WebView에서 레시피대로 입력(5.3). 공식 사이트 위에 한글 말풍선 오버레이.
4. 사람 확인 지점(2.2)에서 멈추고 안내한다.
5. 사용자가 최종 제출 → 확인번호·QR·PDF를 지갑에 저장, 홈 위젯 갱신.
6. 레시피 실행 실패(선택자 없음 등) → 즉시 수동 모드로 전환(값 복사 버튼 + 공식 사이트) + 익명 실패 리포트 전송(9.4).

## 7. 개인정보·보안 설계 (필수)

### 7.1 원칙
- 여권·예약 서류·개인 프로필 등 개인정보(PII)는 **운영자 서버(Firebase 포함)로 절대 보내지 않는다**.
- PII가 기기 밖으로 나가는 유일한 경로: 사용자가 실행한 자동 입력으로 **허용 목록에 있는 정부 공식 도메인(HTTPS)**에 제출될 때.

### 7.2 문서 인식
- **여권**: ML Kit Text Recognition v2 **번들형**(모델을 앱에 포함)으로 MRZ 인식 → ICAO 9303 체크디지트 검증.
  - ML Kit은 이미지 등 입력 데이터를 기기 안에서 처리한다. 다만 API 성능·사용량 메트릭을 Google로 보내므로 개인정보 안내에 고지한다 `[재확인]`.
- **NFC 칩 검증(2차)**: JMRTD로 BAC/PACE 접속 → DG1 읽기 → SOD 전자서명 검증. **DG2(얼굴 사진)는 읽지 않는다**(생체정보 이슈 회피).
- **숙소·항공 서류**: 촬영 OCR + 규칙 기반 추출(날짜·예약번호 정규식). 가능하면 다른 앱의 '공유하기'로 PDF·텍스트를 받는 경로를 우선한다. 지원 기기에서는 기기 내 LLM(Gemini Nano, ML Kit GenAI) 보조를 선택적으로 쓴다. 실패 시 수동 확인.

### 7.3 저장
- Android Keystore 기반 AES-GCM 암호화 + 생체 인증 잠금.
- 원본 이미지는 값 추출 직후 삭제.
- 자동 백업 제외(`android:allowBackup`/`dataExtractionRules`), 민감 화면 `FLAG_SECURE`.
- 여행 종료 후 자동 파기 옵션(파기 전 설명 + 미루기).
- 여권 사본 보관은 사용자 선택(기본 끔), 암호화.

### 7.4 권한·SDK
- 사진은 **Photo Picker**(저장소 권한 불필요). 카메라는 촬영 시에만.
- 교통 앱 설치 확인은 `QUERY_ALL_PACKAGES`를 쓰지 말고, 매니페스트 `<queries>`에 필요한 패키지만 선언한다.
- 분석·크래시 SDK가 입력 화면 내용이나 WebView 로그를 수집하지 않게 막는다. Analytics 이벤트에 여권·여행 일정 등 PII를 넣지 않는다. 광고 ID 수집을 끈다.
- 클립보드 복사 후 일정 시간 뒤 지우기 옵션.

### 7.5 레시피 보안
- 레시피는 **선언형 데이터(JSON)만** 허용한다. 원격으로 받은 JavaScript를 실행하지 않는다. (레시피 서버가 탈취되면 보관함을 읽어 외부로 보내는 경로가 생기기 때문)
- 모든 국가 팩과 레시피는 서명(Ed25519 권장)하고, 앱에 내장한 공개키로 검증한 뒤 적용한다.
- 레시피는 `official_url_patterns`에 일치하는 HTTPS 페이지에서만 실행한다.

### 7.6 신뢰 증명
- 문서 인식·보관함·입력기 핵심 모듈은 공개 저장소로 공개하는 것을 전제로 작성한다(12.6절 브랜치 보호와도 연결).

## 8. 정책·법률 요구사항

### 8.1 Google Play
- **오인 주장 정책**: 권한 없이 정부 서비스를 제공·중개하는 것처럼 보이면 안 된다.
  - 앱 이름·아이콘에 정부 연상 요소 금지. '입국 준비' 탭 상단과 스토어 설명에 "정부 기관과 제휴하지 않았습니다"를 고지한다.
  - 정보 출처를 명시하고, 공식 사이트 화면을 그대로 보여주며, 사용자가 직접 제출한다.
- **접근성 API**: 공식 앱 조작용으로 쓰지 않는다. (자율 동작은 금지, 결정적 자동화도 고지·동의 필요 `[재확인]`)
- **데이터 보안 섹션**: 기기 안에서만 처리하는 데이터는 '수집'이 아니다. 다만 WebView로 정부 사이트에 제출되는 경로는 해석이 애매하므로 보수적으로 기재한다.
- **민감 정보**: 카메라·여권 처리에 대해 눈에 띄는 고지와 동의 화면을 둔다.
- **결제**: 제휴 링크는 앱 밖에서 쓰는 실물 상품·서비스라서 Play 결제 대상이 아니다.
- **타깃 API**: 최신 요구 수준을 확인하고 맞춘다 `[재확인]`.

### 8.2 한국 법
- **여권번호는 고유식별정보**다. 운영자 서버로 받지 않는 구조를 유지한다(받는 순간 별도 동의·암호화 의무 발생).
- **신고 책임은 신청자 본인**이다. OCR 오류가 입국 거부로 이어질 수 있으므로 원본 대조 화면이 필수다.
- **포지셔닝**: "대행"이 아니라 "본인 입력 보조 도구"로 표현한다. 무료 입국카드에 수수료를 받지 않는다.
- **제휴 링크**: 표시광고법상 추천·보증 시 경제적 이해관계 표시 기준을 따른다. 제휴 프로그램별 앱 게재 허용 여부와 표기 문구 규정을 확인한다 `[확인 필요]`.
- **보험·환전·카드**: 수수료를 받지 않는다. 보험 모집·금융상품 판매 중개 규제 대상이 될 수 있어, 법률 검토 전까지 공식 비교·안내 링크만 둔다.
- **가족 모드**: 동행자(미성년자 포함) 서류는 보호자 기기에만 저장하고, 등록 시 동의 확인 문구를 표시한다.

### 8.3 콘텐츠 저작권
- 블로그·가이드북·여행사 페이지·커뮤니티 문장을 복제하지 않는다. 설명은 직접 작성한다.
- Wikivoyage·Wikipedia(CC BY-SA)를 쓰면 출처를 표기한다. 파생 콘텐츠도 같은 라이선스가 됨을 인지한다.
- 외교부 공공데이터(입국허가요건 등)는 이용허락범위 제한 없음 `[재확인]`.
- 지하철 공식 노선도 이미지는 저작권이 있으므로 공식 링크로 연결하거나 오픈데이터로 직접 도식화한다.
- 상품 포장 사진·브랜드 이미지는 쓰지 않는다(텍스트·아이콘). 특정 브랜드명도 중립성을 위해 쓰지 않는다.

### 9.2 "앱은 엔진, 정책·양식·콘텐츠는 데이터"
- 정책이 바뀌어도 앱 업데이트 없이 데이터만 바꿔 대응한다.

| 변경 유형 | 예시 | 반영 수단 | 속도 |
|---|---|---|---|
| 긴급 차단·공지 | 사이트 개편으로 자동 입력 오작동 | Remote Config 스위치(국가·양식별 자동 입력 끄기 → 수동 모드), 배너 | 수 분~수 시간 |
| 규칙·양식 변경 | 기한·필드·수수료·URL 변경 | 서명된 국가 팩 새 버전을 Hosting에 배포 + Remote Config 버전 번호 갱신 | 당일 |
| 새로운 절차 유형 | 셀피 단계 신설, 앱 전용 전환 | 앱 업데이트(Play 인앱 업데이트, 최소 버전 강제) | 수일 |

- 모든 팩에 `schema_version`. 구버전 앱이 모르는 스키마를 만나면 오작동하지 말고 수동 모드로 전환.
- 설치 파일에 **기본 팩**을 내장해 서버가 막혀도 앱이 동작하게 한다.

### 9.3 Firebase 무료(Spark) 제약과 사용 방식 `[재확인]`

| 서비스 | 제약 | 사용 |
|---|---|---|
| Hosting | 저장 10GB, 전송 하루 360MB | 서명된 국가 팩·레시피·순위 파일 배포(주력) |
| Firestore | 1GiB, 읽기 5만/일, 쓰기 2만/일 | 익명 실패 리포트, 찜 수 집계, ARIA 하트비트 |
| Remote Config | 무료 | 스위치, 버전 포인터, 최소 버전, 배너 |
| FCM | 무료 | 국가별 정책 변경 알림(토픽) |
| Analytics·Crashlytics·App Check | 무료 | 오류 감지, 남용 방지 |
| Cloud Storage | 2026-02-03부터 Blaze 필요 → **사용 안 함** | — |
| Cloud Functions | Spark 불가 → **사용 안 함** | 서버 로직은 ARIA가 대신 |

- 한도를 넘으면 과금 대신 서비스가 제한된다 → 기본 팩 + 로컬 캐시로 버틴다.
- **텍스트 중심**: 사진은 Firebase로 서비스하지 않는다. 아이콘·일러스트, 앱 내장 대표 이미지, 위키미디어 공용 썸네일 외부 링크(라이선스 표기)를 쓴다.
- **버전 확인 후 다운로드**: Remote Config 버전이 바뀐 국가 팩만 받는다. 팩은 '국가 기본 + 도시 추가'로 나누고 바뀐 부분만 갱신.
- 참고 규모: 텍스트 팩 200KB 가정 시 하루 약 1,800회 다운로드 가능.

### 9.4 Firestore 데이터 (PII 없음)

- `favorite_counts/{city_id}`: `count`(increment만 허용).

### 9.6 FCM
- 토픽 `country_{ISO2}`. 사용자가 여행을 만들거나 찜하면 기기에서 구독. 여행 일정 자체는 서버에 올리지 않는다.

### 9.7 교통 앱 연결
- 국가 팩에 국가별 교통 앱 목록(패키지명, 연결 방식)을 둔다. 예: 태국 Grab·Bolt / 일본 GO·Uber. 동남아에는 Uber가 없다 `[재확인]`.
- 3단계 연결:
  1. 공식 문서로 링크 형식을 공개한 앱은 목적지까지 채워서 연다.
     - Google 지도: `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}&travelmode=transit`
     - Uber: `https://m.uber.com/ul/?action=setPickup&pickup=my_location&dropoff[latitude]=..&dropoff[longitude]=..` `[재확인]`
     - Grab 등: 공식 규격이 없으면 2단계로 `[확인 필요]`
  2. 앱 실행 + 목적지 주소(현지어) 클립보드 복사
  3. 미설치 시 Play 스토어로 연결
- 연결 실패 시 자동으로 다음 단계로 넘어간다.
- 출국 전 '앱 준비' 체크리스트: 설치, 가입, 카드 등록, 전화번호 인증을 한국에서 미리.

### 9.8 오프라인
- 찜 → WorkManager `NetworkType.UNMETERED`(설정에서 변경 가능) 조건으로 국가·도시 팩 자동 다운로드.
- 팩 내용: 입국 서류 안내, 교통·결제·음식·계절·안전, 현지어 카드, 긴급 연락처, 숙소 주소(현지 글자), 쇼핑 리스트, 꼭 챙길 물건 규칙.
- 지도 파일은 제공하지 않는다(무료 한도 초과). Google 지도 앱의 오프라인 지역 저장을 단계별로 안내.
- 도움 탭 전체와 입국 QR은 항상 오프라인 동작.
- 현지어 음성은 `TextToSpeech.isLanguageAvailable()`로 확인하고, 없으면 카드 표시만.

## 12. ARIA 운영 연동

### 12.1 전제
- ARIA는 운영자의 Windows PC에서 24시간 도는 Python 기반 자율 에이전트다. 텔레그램 봇 인터페이스(CMD:v1 JSON 명령 형식)와 크롤링·뉴스 수집·번역 파이프라인을 이미 갖고 있다.
- **ARIA 본체 코드는 이 저장소에 없다.** 이 저장소에는 `ops/aria/`에 ARIA가 불러 쓸 수 있는 **독립 모듈과 명확한 인터페이스**를 만든다. ARIA 쪽 연결은 운영자가 따로 한다.
- 역할 분담: 감지·증거 수집은 ARIA, 판단·수정은 Claude(로컬 헤드리스), 승인은 사람(텔레그램 + PR 머지), 배포는 GitHub Actions.

### 12.2 운영 흐름
1. **감지**(하루 1~2회, LLM 없이 결정적 처리): 다음 변경을 확인한 뒤, 변경 지문(diff 해시)과 증거 스냅샷을 저장한다.
   - 외교부 입국허가요건 API 전날 대비
   - 양식 페이지 구조 해시
   - 각국 공지 페이지
   - 기존 뉴스 파이프라인에 입국정책 키워드 추가(TDAC, ETIAS, arrival card 등)
2. **현장 신호**: Firestore `field_reports`를 집계한다. 실패율이 임계치를 넘으면 해당 양식의 `kill_autofill_*`를 자동으로 켜고(안전한 방향) 텔레그램으로 알린다.
3. **승인 요청**: 텔레그램으로 변경 요약과 증거 링크를 보낸다. 운영자가 CMD:v1 '처리' 명령으로 승인한다.
4. **수정**: ARIA가 로컬에서 Claude Code를 헤드리스로 실행한다.
   - `claude -p "<작업 지시>" --allowedTools "<필요 도구만>" --output-format json`
   - CLAUDE.md 규칙이 적용되도록 일반 모드로 실행한다(`--bare`는 CLAUDE.md를 읽지 않으므로 사용 금지) `[재확인]`.
   - 증거 파일과 해당 국가 팩을 입력으로 JSON·레시피를 수정하고, 스키마 검증과 선택자 확인(제출 금지)을 마친 뒤 `claude/` 브랜치에 푸시하고 PR을 만든다.
5. **머지**: 운영자가 GitHub에서 검토하고 머지한다. 비자 필요 여부·기한 등 정책 의미가 바뀌는 수정은 반드시 사람이 확인한다.
6. **배포**(GitHub Actions): 팩 서명 → Firebase Hosting 배포 → Remote Config 버전 갱신 → FCM 토픽 알림.

### 12.6 권한과 저장소
- ARIA 자격증명 최소화: 이 저장소 전용 fine-grained GitHub 토큰(쓰기), Remote Config 전용 서비스 계정. **Hosting 배포 권한은 ARIA에 주지 않는다**(GitHub Actions secrets에만).
- 원칙: 안전한 방향(자동 입력 끄기, 경고 배너 켜기)은 ARIA가 자동으로, 위험한 방향(새 정책값 게시, 자동 입력 다시 켜기, 레시피 변경)은 사람 승인 후.
- main 브랜치 보호(PR 리뷰 필수). GitHub 무료 플랜에서 비공개 저장소는 브랜치 보호가 제한되므로 공개 저장소를 기본으로 한다 `[확인 필요]`.

### 12.7 ARIA 감시 (단일 장애점 대책)
- GitHub Actions가 하루 1회 `ops/heartbeat`를 확인한다. 3일 이상 끊기면 운영자에게 알리고 Remote Config `stale_banner`를 켠다(앱에 "정보 점검이 늦어지고 있어요" 배너 표시).

## 15. 작업 규칙 (CLAUDE.md에 그대로 넣을 것)

1. **정부 사이트 제출 금지**: 테스트·개발 중 어떤 경우에도 실제 정부 사이트에 제출하지 않는다. 자동화 테스트는 필드 존재·선택자 확인까지만 하고 제출 버튼 앞에서 멈춘다. 가짜 데이터로 제출하는 것은 허위 신고다.
2. **캡차 우회 금지**, 접근성 API로 다른 앱 조작 금지, 서버 헤드리스 브라우저로 개인정보 처리 금지.
3. **PII 금지 구역**: 로그, Crashlytics, Analytics, Firestore, 저장소, 이슈·PR 설명에 여권·예약·개인 정보를 넣지 않는다.
4. **테스트 데이터**: ICAO 9303 표본(가상 국가) 같은 가짜 데이터만 쓴다. 실제 여권 이미지를 저장소에 넣지 않는다.
5. **레시피는 선언형 JSON만**. 원격 JavaScript 실행 코드 금지. 서명 검증 없는 팩 적용 금지.
6. **사실을 지어내지 않는다**: 비자 규칙, 수수료, 제출 기한, 긴급번호, 딥링크 형식, 선택자 등 확인되지 않은 값은 `[확인 필요]`로 남기고 운영자에게 질문한다. 모든 정책 데이터에 `source`와 `last_verified`를 채운다.
7. **콘텐츠 복제 금지**: 외부 글·이미지·노선도·상품 사진을 복제하지 않는다. CC BY-SA 자료는 출처를 표기한다.
8. **쉬운 말 우선**: UI 문구는 3.4절 규칙을 따른다. 새 전문 용어를 쓰기 전에 쉬운 말을 먼저 정한다.
9. **새 의존성**: 네트워크를 쓰는 라이브러리나 SDK를 추가하기 전에 이유와 수집 데이터를 설명하고 승인을 받는다.
10. **무료 한도 준수**: Cloud Storage·Cloud Functions를 쓰지 않는다. Firebase로 이미지를 서비스하지 않는다.
11. **제휴 규칙**: 제휴 링크에는 항상 '제휴' 표시. 보험·금융 상품에는 제휴 링크를 넣지 않는다. 수수료로 추천 순서를 바꾸지 않는다.
12. **안전한 방향 우선**: 자동 입력이 불확실하면 수동 모드로 떨어뜨린다. 정책 의미가 바뀌는 변경은 사람 승인 없이 게시하지 않는다.
13. **작업 방식**: 마일스톤 단위로 작업하고, 끝날 때마다 완료 기준 충족 여부와 남은 `[확인 필요]` 목록을 보고한다. PR 설명에는 변경 이유와 출처를 적는다.
14. **헤드리스 실행 시**(ARIA가 호출): 지시받은 국가·양식 범위만 수정하고, 스키마 검증을 통과한 경우에만 `claude/` 브랜치로 PR을 만든다. main에 직접 푸시하지 않는다.

## 부록 B. 이용 시나리오 (수용 테스트 기준으로 사용)

**A. 58세 부부, 첫 해외여행, 방콕 4박**

- 2일째: 인터넷이 끊겨도 '여기로 가기', 기사님께 보여주기 카드

**C. 위기: 여권 분실**
