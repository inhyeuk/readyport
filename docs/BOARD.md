# 게시판 운영 안내 (2026-10-08)

운영자 요청(그대로): *"게시판의 기능을 넣어줘. 게시판은 하단 고정 메뉴에 추가해 주고, Q&A와 자유로운 토론을 할 수 있도록 하기 위함이니 그 목적에 맞춰 구성해줘. 게시할 수 있고 답글도 달 수 있도록 해줘. 스토리지 공간 이슈가 있으니 이미지/ 동영상 등록은 가능하도록 하되, 설정에서 off로 해서 나중에 필요할 경우 on으로 변경하면 기능이 활성화되도록 해줘. 그 외 게시판의 주요 기능은 우수 게시판의 사례를 참고해서 적용해줘. 그리고 최대한 아이콘, 이미지 등을 활용해서 예쁘게 구성해줘"*

설계 기록 `docs/ARCHITECTURE.md` '게시판' · 화면 `docs/design/DESIGN_SPEC_2026-10-01.md` 부록 L · 보고 `docs/design/BOARD_REPORT.md`.

## 1. 무엇이 어디에 있나

| 무엇 | 어디 |
|---|---|
| 하단 탭 | `둘러보기 · 내 여행 · **게시판** · 도움 · 설정` (자녀 폰 모드에는 없음) |
| 게시판 둘 | **Q&A**(질문과 답변 — 입국 서류·비자·공항) / **자유 토론**(여행 이야기·알뜰 정보) |
| 서버 | Firestore `board_posts`(+ `comments`·`likes`·`reports` 하위), `board_users`, `config/board`, `config/admins` |
| 규칙 | `firebase/firestore.rules` '게시판' 절 — 테스트 `cd tools/firestore && npm test` (에뮬레이터) |
| 색인 | `firebase/firestore.indexes.json` (목록·정렬·나라·검색·답글 알림·내 기록 지우기용) |
| 사진·동영상 규칙 | `firebase/storage.rules` (켜기 전에는 배포하지 않는다 — 5절) |
| 앱 코드 | `app/src/main/java/com/readyport/board/`(데이터·검사·서버), `ui/board/`(화면) |

## 2. 처음 출시 전에 운영자가 할 일 (순서대로)

1. **Firebase 콘솔 › Authentication › 로그인 방법 › 익명 사용 설정.** 꺼져 있으면 앱은 글을 읽기만 하고, 쓰기를 누르면 `게시판 글쓰기를 아직 준비하고 있어요`라고 말한다.
   - App Check를 Firestore에 강제하고 있다면 Authentication에도 같은 App Check 등록이 필요하다(콘솔 › App Check › Authentication). 디버그 빌드는 디버그 토큰.
2. **규칙·색인 배포** (머지 뒤, 운영자 PC):
   ```
   firebase deploy --only firestore:rules,firestore:indexes --project readyport-app
   ```
   색인은 만들어지는 데 몇 분 걸린다. 그동안 목록이 비어 보일 수 있다(콘솔 › Firestore › 색인에서 `빌드 중` 확인).
3. **운영자 ID 등록** (4절).
4. **데이터 보안 양식·개인정보 처리방침**: `docs/play/DATA_SAFETY_0.6.0.md` 순서대로 Play Console 다시 내기(콘텐츠 등급은 `docs/play/CONTENT_RATING_0.6.0.md`), `hosting/public/privacy/index.html`(게시판 절 추가됨)을 법률 검토(C8) 뒤 Hosting에 배포.
5. (선택) 첫 고정 글: 운영자 계정으로 `게시판 이용 안내` 글을 써서 고정(4절 화면에서 `맨 위에 고정`).

## 3. 데이터와 공개 범위

| 문서 | 내용 | 누가 읽나 | 누가 쓰나 |
|---|---|---|---|
| `board_posts/{id}` | 게시판 종류·제목·본문·나라 태그·검색 낱말·(켰을 때) 사진 주소·닉네임·**익명 게시판 ID**·시각·댓글/추천/신고 수·해결됨·채택 답·고정·가림·지움 | **누구나**(로그인 없이). 가린 글은 운영자·글쓴이만 | 글쓴이(익명 로그인) · 숫자는 짝 규칙 · 고정/가림은 운영자 |
| `…/comments/{id}` | 본문·닉네임·게시판 ID·답글 대상(댓글 id·ID·닉네임)·알림 대상(최대 2명의 ID)·시각·추천/신고 수 | 누구나(가린 댓글 제외) | 쓴 사람 · 운영자(가림) |
| `…/likes/{uid}` | 추천한 사람 ID·글 id·시각 | 본인만 | 본인 |
| `…/reports/{uid}` | 신고한 사람 ID·이유·시각 | **운영자만**(본인은 자기 것만) | 본인(한 번) |
| `board_users/{uid}` | 닉네임·처음 만든 시각·글 수·마지막 글/댓글 시각(간격 확인용) | 누구나(닉네임) | 본인 |
| `config/board` | `mediaEnabled`(사진·동영상 스위치) | 누구나 | **운영자만** |
| `config/admins` | `uids`: 운영자 게시판 ID 목록 | 누구나(ID일 뿐) | **아무도 앱에서 못 쓴다 — 콘솔에서만** |

- **여권·여행 정보와는 길이 다르다.** 게시판 코드는 지갑·여행 장부를 읽지 않는다. 이름·이메일·전화번호를 받지 않는다(익명 로그인).
- 사람이 직접 쓴 글에 개인정보가 섞일 수 있어 올리기 전에 앱이 살핀다: 여권 번호·여권 아래 두 줄(MRZ)·주민등록번호는 **막고**, 전화번호·이메일은 **경고**(대사관 번호처럼 공개된 번호일 수 있어 `이대로 올리기` 가능). 욕설은 `＊`로 가려 올린다.
- 이 휴대폰에만: 규칙 동의, 닉네임 사본, **차단 목록**, 답글 확인 시각·안 읽은 수(DataStore `board`, 백업 제외).

## 4. 운영자 ID 등록·관리 화면

1. 운영자 휴대폰에서 게시판에 글이나 댓글을 한 번 쓴다(익명 ID가 생긴다).
2. **설정 › 게시판 › 내 게시판 ID › `ID 복사`**.
3. Firebase 콘솔 › Firestore › `config` 컬렉션 › 문서 `admins`(없으면 만든다) › 필드 `uids`(배열)에 붙여 넣는다.
   ```
   config/admins  { uids: ["<복사한 ID>"] }
   ```
4. 앱을 다시 열면 운영자 표시가 생긴다: 글·댓글 `⋯` 메뉴에 `맨 위에 고정 / 가리기 / 문서째 지우기`, 설정 › 게시판에 `게시판 사진·동영상 올리기` 스위치와 `신고·가림 관리`. 운영자가 쓴 글에는 `운영자` 배지.
- 앱을 지우거나 `내 게시판 기록 모두 지우기`를 하면 **새 익명 ID**가 된다 → `uids`를 다시 고친다(옛 ID는 지운다).
- 규칙은 `config/admins`를 **앱에서 누구도(운영자 자신도) 쓸 수 없게** 막는다.

## 5. 사진·동영상 올리기 (기본 꺼짐)

- 만들어 두었지만 **꺼 둔** 기능이다. 꺼져 있으면 글쓰기에 사진·동영상 버튼이 아예 없고, 규칙도 사진 주소가 든 글을 거절한다.
- **⚠ Cloud Storage for Firebase는 Blaze(종량제) 요금제가 필요하다**(2026-02-03부터 — ARCHITECTURE 9.3). 지금 `readyport-app`은 Spark라 버킷이 없다. 켜려면:
  1. 콘솔 › 사용량 및 결제 › **Blaze로 업그레이드** + **예산 알림**(예: 월 1만 원, 50%·90%·100%) 걸기.
  2. 콘솔 › Storage › 시작하기(위치는 Firestore와 같은 곳).
  3. `firebase deploy --only storage --project readyport-app` (`firebase/storage.rules` — 내 경로만, 사진 2MB·동영상 20MB, 스위치가 꺼지면 아무도 못 올림).
  4. 운영자 앱 › 설정 › 게시판 › **게시판 사진·동영상 올리기** 켜기(→ `config/board.mediaEnabled = true`).
- 앱이 올리기 전에: 사진은 긴 변 1600px로 줄이고 **다시 그려 EXIF(위치·기기·시각)를 모두 지운다**(최대 4장), 동영상은 30초·20MB 이하만, 트랙만 옮겨 담아 위치 정보를 뺀다. Storage가 없거나 막히면 `지금은 사진·동영상을 올릴 수 없어요. 글만 올려 주세요.`
- 끄면: 새 사진은 막히고, 이미 올린 사진은 그대로 보인다(지우려면 콘솔 › Storage `board/`).
- 비용 감각(참고, [재확인]): 저장 GB당·내려받기 GB당 과금. 사진 한 장 약 300KB면 1GB ≈ 3,300장.

## 6. 신고·가림(임시조치)·지우기

- **신고**(이유 6가지: 광고·도배 / 욕설·차별·괴롭힘 / 개인정보 / 불법 정보 / 틀린 안내 / 그 밖의 문제) — 한 사람 한 번. 신고가 **3번** 쌓이면 모든 휴대폰에서 그 글이 먼저 접힌다(`신고가 쌓여 가려진 글이에요` + `그래도 보기`). 서버에서 지우는 것은 아니다.
- **운영자 처리**(설정 › 게시판 › 신고·가림 관리): 신고 많은 차례로 글·댓글. 줄마다
  - `가리기` = **임시조치**: 글쓴이와 운영자만 볼 수 있게 된다(규칙이 다른 사람의 읽기·목록을 막는다). `다시 보이기`로 되돌린다.
  - `신고 지우기` = 검토해 보니 문제없음(신고 수 0).
  - `문서째 지우기` = 되돌릴 수 없다.
- **권리 침해 신고(정보통신망법 제44조의2 — 명예훼손·사생활 침해)**: 당사자가 메일(개인정보 처리방침 연락처)로 삭제를 요청하면
  1. 그 글을 바로 `가리기`(임시조치, 최대 30일).
  2. 글쓴이에게 알릴 길이 없다(익명 — 연락처를 받지 않는다) → 게시판에 `운영자가 가린 글이에요`로 보이게 두고, 글쓴이가 메일로 이의를 제기하면 검토.
  3. 30일 안에 판단해 `문서째 지우기` 또는 `다시 보이기`. 요청 메일과 처리 날짜는 운영자 메일함에 남긴다.
- **차단**: 사용자가 `이 사람 차단하기`를 누르면 **그 휴대폰에서만** 그 사람의 글·댓글이 가려진다(서버에 보내지 않음, 설정에서 모두 풀기).
- **간격**(규칙이 서버 시각으로 막는다): 글 30초, 댓글 10초. 앱도 미리 `n초 뒤에 다시 눌러 주세요`라고 말한다.

## 7. 답글 알림 (서버 토큰 없음)

- 서버에서 보내는 알림이 아니다. 앱이 **켤 때 한 번 + 하루 한 번**(챙길 일 쓸기 작업·팩 받기 작업) 직접 확인한다: 내 글의 댓글·내 댓글의 답글(묶음 질의 `comments where notify array-contains 내 ID`).
- 이 휴대폰 알림 `내 글에 새 댓글 2개` + 짧은 미리보기 한 줄(욕설 그물에 걸리면 숫자만, 잠금 화면에서는 미리보기 숨김), 게시판 탭에 빨간 숫자. 설정 › 게시판 › `게시판 답글 알림`(기본 켬)으로 끈다. 로그인한 적이 없으면 아무것도 묻지 않는다.

## 8. 무료 한도(Spark)에서의 감각 [재확인]

- 읽기 5만/일: 목록 한 쪽 = 글 20 + 고정 ≤5 읽기. 목록은 **내가 쓰거나 지울 때**, 그리고 게시판을 다시 볼 때 **1분이 지났을 때만** 다시 불러온다(탭을 오갈 때마다 읽지 않는다). 하루 목록 2천 번 정도가 한도의 큰 몫.
- 쓰기 2만/일: 글 하나 = 2쓰기(글 + 이용자), 댓글 = 3, 추천·신고 = 2.
- 한도를 넘으면 그날은 게시판이 `인터넷이 있어야 보여요`처럼 실패한다(과금은 없다 — Spark). 사용자가 늘면 Blaze 전환을 검토.

## 9. 알려진 한계

- **검색**: Firestore에는 전문 검색이 없다. 글을 올릴 때 제목·본문 낱말(한글은 두 글자씩 겹쳐 자름, 영문·숫자는 통째) 최대 40개를 `keywords`로 저장하고 `array-contains` 하나로 묻는다. 그래서 ① 본문이 길면 뒤쪽 낱말은 찾히지 않을 수 있다 ② 찾을 때는 최신 순만 ③ 여러 낱말은 앱이 한 번 더 거른다(한 쪽에 20개보다 적게 보일 수 있다 — `글 더 보기`).
- 닉네임을 바꿔도 예전 글의 닉네임은 그대로다(글에 복사해 둔 값).
- 익명 계정이라 앱을 지우면 예전 글을 고치거나 지울 수 없다(화면에서 미리 알린다). 운영자에게 메일로 요청하면 운영자가 지운다.
- 댓글이 없는 글을 지우면 그 글의 추천·신고 하위 문서가 남는다(ID·시각뿐). 필요하면 콘솔에서 정리.
- 동영상 재생은 휴대폰의 기본 앱으로 연다(새 플레이어 라이브러리를 넣지 않았다).
