# Play Console 데이터 보안(Data safety) — 0.6.0 입력 순서표

> 2026-10-09 작성. 0.6.0(versionCode 8)을 올리기 **전에** Play Console › 앱 콘텐츠 › 데이터 보안에서 이 순서대로 고치고 '제출'한다.
> 출발점 = 0.5.0까지 신고한 상태(`docs/play/DATA_SAFETY.md` 1~4절, 2026-09-29 제출 — 개인 정보 '5종'(WebView로 정부 사이트에 넣는 값, 보수적 기재·선택·앱 기능), 진단·기기 ID 필수, 앱 상호작용 선택, 공유 없음).
> 새로 생긴 것 = 게시판(익명 로그인·글·댓글·닉네임·추천·신고)과 공지 알림(FCM 토픽). 근거 코드: `board/FirestoreBoardBackend.kt`, `firebase/firestore.rules`, `cloud/CloudSync.kt`.
> **법률 검토 전 초안**이고, 아래 Google 정의는 Play 고객센터 '데이터 보안 섹션' 안내를 기억으로 옮긴 것이다(제출 직전 콘솔의 물음표 도움말로 문구 확인 — `[확인]` 표시).

## 1. 첫 화면 '데이터 수집 및 보안'

1. **앱에서 필수 사용자 데이터 유형을 수집하거나 공유하나요?** → `예` (그대로)
2. **앱에서 수집하는 모든 사용자 데이터가 전송 중에 암호화되나요?** → `예` (그대로 — Firebase SDK·Hosting 모두 HTTPS)
3. **앱에서 지원하는 계정 생성 방법** → 판단이 갈리는 곳 `[확인]`
   - 사실: 게시판에 처음 글·댓글을 쓰거나 추천·신고를 누르면 앱이 **Firebase 익명 로그인**으로 계정(게시판 ID)을 만들고, 이용자가 **닉네임**을 정한다. 아이디·비밀번호·이메일·전화는 없다. 콘솔에서 익명 계정 30일 자동 정리는 꺼 두었으므로 계정은 남는다.
   - **권장(보수적)**: `기타`를 고르고 설명에 *Anonymous account created automatically when the user first posts on the community board (nickname only, no email/phone/password).* — 계정 삭제 요건(앱 안 경로 + 웹 요청 경로)을 함께 채운다(4번).
   - 다른 해석: 이용자가 '계정을 만든다'는 행동을 하지 않으므로 `앱에서 사용자가 계정을 만들 수 없음`도 가능하다. 다만 닉네임이 붙은 영구 ID라 심사에서 '계정'으로 볼 위험이 있어 권장하지 않는다.
4. **계정 삭제 URL**(3에서 `기타`를 고르면 나온다) → `https://readyport-app.web.app/privacy/#board-delete`
   - 이 주소의 절(`<p id="board-delete">`)이 앱 안 경로(설정 › 게시판 › 내 게시판 기록 모두 지우기)와 메일 요청(inhyeuk@gmail.com)을 설명한다. **0.6.0 개인정보 처리방침을 Hosting에 배포한 뒤** 이 주소를 넣는다(배포 전에는 이 절이 없다).
5. **사용자가 데이터 삭제를 요청할 수 있는 방법을 제공하나요?** → `예`
   - 앱 안: 글·댓글 하나씩 지우기, 설정 › 게시판 › `내 게시판 기록 모두 지우기`(내 글·댓글 내용·닉네임·추천·이용자 문서).
   - 메일: 앱을 지웠거나 남는 것(아래)을 지우고 싶으면 개인정보 처리방침의 연락처로 요청 → 운영자가 콘솔에서 지운다.
   - 남는 것(솔직하게): 댓글이 달린 글·댓글은 내용·닉네임만 비우고 자리(게시판 ID·시각)가 남는다, 신고 기록, Firebase의 익명 계정 자체 — 모두 메일 요청으로 운영자가 지운다.
   - (선택 질문) **일부 데이터만 삭제 요청** → `예`(글·댓글 하나씩 지우기가 있으므로).

## 2. 데이터 유형 고르기 → 유형마다 질문

콘솔 순서: 유형 목록에서 체크 → 체크한 유형마다 ① 수집/공유 ② 일시적으로 처리 ③ 필수/선택 ④ 목적.

### 2-1. 개인 정보 › 사용자 ID — **새로 체크**
- 무엇: Firebase 익명 로그인 UID(`authorUid`·`board_users/{uid}`·추천·신고 문서). 글·댓글과 함께 저장돼 **누구나 읽을 수 있다**.
- Google 정의(요지): 식별 가능한 사람과 관련된 식별자 — 계정 ID·계정 번호·계정 이름 등. 익명이어도 같은 사람의 글을 묶는 계정 ID이므로 해당.
- ① 수집 `예` · 공유 `아니요` ② 일시 처리 `아니요` ③ `선택`(게시판에 쓰지 않으면 만들지 않는다 — 읽기는 로그인 없이) ④ 목적 `앱 기능`, `계정 관리`, `사기 방지, 보안, 규정 준수`(글 30초·댓글 10초 간격, 신고 한 사람 한 번, 차단·운영자 가림).

### 2-2. 개인 정보 › 이름 — **체크돼 있는지 확인, 없으면 체크**
- Google 정의(요지): 이용자가 자신을 부르는 방식 — 성·이름 **또는 닉네임**. 게시판 닉네임(2~12자, 공개)이 여기에 든다 `[확인 — 정의 문구에 nickname이 있는지]`.
- 0.5.0의 '개인 정보 5종'에 이름이 이미 있으면(정부 사이트 입력 때문에) 그대로 두고 목적만 확인: `앱 기능`. 어떤 다섯이었는지는 저장소에 기록이 없다 — 콘솔에서 본다.
- ① 수집 `예` · 공유 `아니요` ② `아니요` ③ `선택` ④ `앱 기능`.

### 2-3. 앱 활동 › 기타 사용자 제작 콘텐츠 — **새로 체크**
- 무엇: 게시판 글(제목·본문·나라 태그·검색 낱말)·댓글·답글(답하는 사람의 ID·닉네임, 알림 받을 사람 최대 2명의 ID 포함)·채택.
- ① 수집 `예` · 공유 `아니요`(2-6 참고) ② `아니요` ③ `선택` ④ `앱 기능`.
- 사진·동영상을 켜면(`config/board.mediaEnabled`) **사진·동영상 › 사진 / 동영상**도 `예(선택, 앱 기능)`로 체크하고 다시 제출한다.

### 2-4. 앱 활동 › 앱 상호작용 — **이미 체크(찜 수). 목적 하나 추가**
- 더해지는 것: 추천(누가·어느 글·시각, 본인만 읽음), 신고(누가·이유·시각, 운영자만 읽음), 마지막 글·댓글 시각과 번호(간격 확인용, `board_users`).
- ① 수집 `예` · 공유 `아니요` ② `아니요` ③ `선택`(그대로) ④ 기존 `앱 기능`·`분석` + **`사기 방지, 보안, 규정 준수`** 추가.
- 추천·신고를 '사용자 제작 콘텐츠'로 볼 수도 있다 — 2-3에 이미 체크했으므로 어느 쪽에 넣어도 신고 누락은 없다.

### 2-5. 메시지 › 기타 인앱 메시지 — **체크하지 않음** `[확인]`
- 댓글·답글은 글 아래 **공개** 대화이고 1:1·비공개 메시지가 없다 → 사용자 제작 콘텐츠(2-3)로 신고한다. 심사에서 메시지로 보라고 하면 2-3과 같은 답(예·아니요·아니요·선택·앱 기능)으로 추가한다.

### 2-6. '공유'가 아닌 이유 (Google 정의, 기억으로 옮김 `[확인]`)
- Play의 '공유' = 앱에서 수집한 데이터를 **제3자에게 넘기는 것**. 다음은 공유로 신고하지 않아도 된다고 안내한다:
  - **서비스 제공업체**에 넘기는 것(개발자를 대신해 처리) → Firebase(Google)에 저장·처리되는 것은 공유가 아니라 '수집'.
  - **이용자가 직접 시작한 행동**으로 이용자가 예상하는 곳에 넘어가는 것 → 이용자가 공개하려고 직접 올린 글·닉네임이 다른 이용자에게 보이는 것.
  - 법적 의무에 따른 이전.
- 불확실한 점: 공개 게시물을 '사용자 시작 전송' 예외로 볼지는 Google 문구가 예시 중심이라 해석의 여지가 있다. 보수적으로 가려면 2-1·2-2·2-3을 `공유 예 — 목적: 앱 기능`으로 바꿔도 손해는 크지 않다(스토어에 '제3자와 공유' 표시가 생길 뿐). **권장: 공유 아니요**(운영자가 제3자에게 넘기지 않고, 이용자가 공개를 골라 직접 올린다 — 개인정보 처리방침 5절과 같은 설명).

### 2-7. 공지 알림(FCM 토픽) — **바뀌는 것 없음**
- 운영자는 토큰을 받거나 저장하지 않고 토픽(`notice_all`·`notice_promo`)만 구독한다. 그래도 **FCM SDK는 기기의 등록 토큰·Firebase 설치 ID를 Google에 보낸다** → Play 기준으로는 앱이 서비스 제공업체(Google)를 통해 '수집'하는 것이다. 이것은 처음 제출(2026-09-29) 때부터 나라 토픽 때문에 이미 `기기 또는 기타 ID — 수집·필수·앱 기능`으로 신고돼 있어 새로 체크할 것이 없다.
- 광고성 소식 동의 여부·날짜, '다시 보지 않기' 기록은 기기 안에만 있다 → 수집 아님. 어떤 토픽을 구독했는지는 Google FCM이 갖지만 운영자가 볼 수 없다.

### 2-8. 그대로 두는 것
- 진단(실패 리포트·ML Kit), 기기 또는 기타 ID, 개인 정보 '5종'(정부 사이트 입력), 위치 아니요, 사진·동영상 아니요, 금융·건강·연락처·캘린더·파일·오디오·웹 기록 아니요.

## 3. 제출 뒤 확인

- 미리보기 화면에 `수집하는 데이터: 개인 정보(사용자 ID·이름 …)·앱 활동(앱 상호작용·기타 사용자 제작 콘텐츠)·앱 정보 및 성능·기기 또는 기타 ID`, `제3자와 공유하는 데이터 없음`, `전송 중 암호화`, `데이터 삭제 요청 가능`이 보이는지.
- 개인정보 처리방침 주소(`https://readyport-app.web.app/privacy/`)는 그대로. **0.6.0 방침(시행 2026-10-09)을 Hosting에 먼저 배포**해야 게시판 설명·`#board-delete`가 실제로 보인다.
- `docs/play/DATA_SAFETY.md` 6절은 이 문서로 대체된다(6절의 초안 표와 다른 점: 이름(닉네임) 추가, 계정 생성·삭제 URL 질문, 앱 상호작용 목적 추가).

> 2026-10-09 메모: 관광지 지도(Google 지도 SDK)·위키백과 요약은 0.6.0/0.6.1에 들어 있지 않다. 이 기능이 들어가는 버전을 낼 때 `docs/play/DATA_SAFETY.md` 7절대로 설문을 다시 본다(진단·기기 ID·앱 상호작용에 Maps SDK 근거 추가, 위치는 '아니요' 쪽 검토).
