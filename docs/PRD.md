# 레디포트 PRD (제품 요구사항)

> 원본: `docs/source/ReadyPort_ClaudeCode_Prompt.md` (2026-09-28 기준). 장 번호는 원본과 같다.
> `[재확인]` = 조사 시점 사실이지만 바뀔 수 있음, 구현 전 공식 출처로 재확인. `[확인 필요]` = 미확정, 추측 금지·운영자에게 질문.
> 부록 B 이용 시나리오는 수용 테스트 기준으로 쓴다.
> 2026-10-01 갱신: 앱 구조 개편(0.2.0~0.3.1 — 탭 4개·나라 화면·비자 온라인 신청·YouTube 영상)과 디자인 개편(`docs/design/DESIGN_SPEC_2026-10-01.md`), 운영자 결정(`docs/design/OWNER_DECISIONS.md` 마지막 절)을 반영했다.

## 1. 제품 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | 레디포트 (ReadyPort) |
| 플랫폼 | Android (Kotlin, Jetpack Compose) |
| 가격 | 무료. 광고 없음. 수익은 수수료 링크(제휴 프로그램 링크, 11.2절)로만 |
| 한 줄 정의 | 해외여행 준비부터 귀국까지 함께하는 '여행 필수품' 앱. 입국 사전신고를 앱이 대신 채워 주고, 사용자는 확인과 최종 제출만 한다 |
| 핵심 대상 | 해외여행 경험이 없는 중학생, 중년 이상. 누구나 설명 없이 쓸 수 있어야 한다 |
| 핵심 약속 | ① 여권 등 개인정보는 폰 밖으로 나가지 않는다 ② 인터넷이 없어도 핵심 기능이 동작한다 ③ 공식 출처와 최종 확인일을 항상 보여준다 |
| 서버 | Firebase 무료 요금제(Spark)만 사용. 서버 로직 없음 |
| 운영 | 정책·양식·콘텐츠 변경 감지와 반영은 ARIA(운영자 PC의 자율 에이전트)가 담당 |

### 1.1 서비스 원칙 (전문가 검토로 확정)

1. 한 화면에는 할 일 하나. 다음에 누를 버튼이 항상 분명해야 한다.
2. 쉬운 말. 중학교 1학년 수준 어휘를 쓰고, 전문 용어에는 풀이를 붙인다.
3. 앱이 채우고 사람은 확인한다. 사용자는 승인과 최종 제출만 한다.
4. 인터넷이 없어도 동작한다. 찜한 여행지와 도움 탭은 항상 오프라인.
5. 현지어는 '읽는 용'이 아니라 '보여주고 들려주는 용'으로 크게 표시한다.
6. 모든 정책 정보에 공식 출처와 최종 확인일을 붙인다.
7. 개인정보는 기기 안에만 둔다.

## 2. 서비스 범위 — 국가·양식

### 2.1 사전신고 유형별 지원 수준

| 유형 | 대상 (2026-09 기준 `[재확인]`) | 지원 수준 | 단계 |
|---|---|---|---|
| 무료 전자 입국카드 (웹) | 태국 TDAC, 말레이시아 MDAC, 싱가포르 SG Arrival Card, 인도네시아 All Indonesia(입국·세관·검역 통합), 일본 Visit Japan Web | 자동 입력 + 사용자 최종 제출 | **MVP** |
| 유료 전자여행허가 (웹 경로 있음) | 캐나다 eTA, 뉴질랜드 NZeTA, 영국 ETA 웹 신청 | 자동 입력. 결제·얼굴 사진·배경 질문은 사용자 | 2차 |
| 공식 앱 전용 (칩 판독·실시간 얼굴 인증) | 호주 ETA, 영국 ETA 앱, 미국 ESTA | 자동화하지 않음. 준비물 체크리스트, 공식 앱 연결, 값 복사 버튼만 | 2차 |
| 시행 예정 | EU ETIAS | 감시만. 시행 확정 시 추가 | 관망 |

참고 사실 `[재확인]`:
- 태국 TDAC는 도착 72시간 이내에만 제출 가능, 무료.
- 싱가포르 SG Arrival Card는 도착 3일 이내 제출.
- 미국 CBP는 ESTA 웹사이트 신규 신청을 폐지하고 모바일 앱으로 단일화하는 안을 제시했다(2025-12). 대리 신청 시에도 신청자 본인 얼굴 사진이 필요하다.
- 영국 ETA는 2026-04-08부터 £20. 대리 신청 가능하나 "다른 사이트·앱을 통해도 결정이 빨라지지 않는다"고 공식 안내.
- EU ETIAS는 2026년 말 목표가 공식 사이트에서 삭제되었고 2027년 연기 가능성이 보도됨.
- 2026년 봄 인도·베트남도 디지털 입국카드를 도입. 양식 수는 계속 늘어나는 추세.

### 2.2 절대 자동화하지 않는 것 (사람 확인 지점)

- 캡차(보안 문자). **우회 시도 금지**.
- 이메일·문자 OTP
- 셀피·실시간 얼굴 인증
- 결제
- 서약, 세관·건강·범죄 이력 질문. 앱이 추정하거나 기본값으로 채우지 않는다. 그림 + 예/아니오로 사용자가 직접 답하게 한다.
- 최종 제출 버튼

## 3. 대상 사용자와 사용 모드

### 3.1 페르소나

| 페르소나 | 특징 | 설계 반영 |
|---|---|---|
| 58세 부부, 첫 해외여행 | 무엇을 모르는지 모름, 작은 글씨·스와이프 어려움 | 쉬운 모드, '지금 할 일' 1개, 음성 안내 |
| 중학생 자녀를 둔 4인 가족 | 보호자가 서류를 한꺼번에 관리 | 가족 모드 |
| 중학생 (첫 해외여행) | '승인', '입국신고서' 같은 말을 모름 | 쉬운 말 사전, 버튼 문구 |
| 저시력 70대 | 큰 글씨, 높은 대비 필요 | 글자 확대 대응, 명도 대비 |
| 배낭여행 경험자 | 빠르게 쓰고 싶음 | 기본 모드 |

### 3.2 쉬운 모드
- 첫 실행 때 "해외여행이 처음이세요?"라고 묻고, 예라고 하면 기본으로 켠다. 설정에서 끄고 켤 수 있다.
- 글자 18~28sp, 버튼 높이 56dp 이상(지금 64dp), 누르는 요소 최소 56dp, 한 화면 한 가지 주요 동작.
- **28sp 예외 (D19, 운영자 승인 2026-10-01)**: 현지인에게 보여 주는 글자(현지어 전체 화면·기사님께 보여주기·도움 선택 문장), 히어로 이름, 큰 숫자는 28sp를 넘어도 된다. 크기: displayLarge 56 · displayMedium 36 · displaySmall 32 · stat 34 · localLarge 56 · localMedium 32 (sp). 그 밖의 글자는 18~28sp 그대로.
- 하단 탭 라벨은 18sp 아래로 줄이지 않는다. 자리가 모자라면 두 줄로 쓴다.
- 화면은 항상 1열. 홈의 여행 준비 카드 넷(출국하는 날·꼭 챙길 물건·귀국 전 확인·내 정보)은 한 줄씩 접어 두고 그 자리에서 펼친다(운영자 결정 8번).
- 스와이프 제스처 금지. 모든 동작은 버튼으로.
- 모든 화면에 '처음으로' 버튼.
- 음성 안내: Android TextToSpeech(기기 내장) 사용.

### 3.3 가족 모드
- 보호자 폰이 대표로 가족 전체의 여권·프로필·QR을 관리한다.
- 자녀 폰에는 자기 QR과 도움 탭만 단순하게 보여준다.
- 자녀 QR을 자녀 폰으로 옮길 때는 서버를 거치지 않고 기기끼리 직접 공유(QR 스캔 또는 시스템 공유)한다.
- 동행자 등록 시 "본인 또는 보호자가 동의했나요?" 확인 문구를 표시한다.

### 3.3.1 날짜를 적는 법 (앱 전체 공통, 다듬기 S2 — 2026-10-03 운영자 결정)

운영자 결정: *"날짜를 입력할 때, 달력에서 선택할 수 있도록 해줘"*

- **달력이 주 입력**이다. 날짜 칸을 누르거나 칸 끝의 달력 단추를 누르면 달력이 열린다. 칸에는 고른 날짜가 `2026-11-03`으로, 그 아래 `11월 3일 (화)`로 보인다.
- **숫자로 적는 길도 그대로** 남는다: 칸 아래 `숫자로 적기`를 누르면 그 칸이 숫자 자판 칸이 된다(하이픈은 앱이 그려 준다). 빠른 사람·TalkBack·글자 200%를 위한 길이다.
- **같은 칸을 쓰는 곳**: 여행 떠나는 날·돌아오는 날, 숙소 체크인·체크아웃, 예약 서류 체크인·체크아웃, 여권 생년월일·만료일.
- **막지 않고 길잡이만**: 달력은 쓸모 있는 달에서 열리고 넘길 수 있는 해만 좁힌다. 정말 있을 수 없는 날(체크아웃이 체크인보다 빠른 날)만 고르지 못하게 하고, 그 밖에 어긋난 날짜는 예전처럼 띠로 알려 준다.
- 달력은 Material 부품이라 날짜 칸 크기를 앱이 바꾸지 못한다 — 터치 영역은 두 모드 모두 48dp이고, 쉬운 모드에서도 숫자로 적는 길이 함께 있어 막히지 않는다.

### 3.4 쉬운 말 사전 (UI 문구 규칙)

| 원래 용어 | 앱 문구 |
|---|---|
| 전자여행허가(ETA) | 미리 받는 입국 허락 |
| 입국신고서 | 도착 전에 내는 입국 카드 |
| 세관 | 가방 속 물건을 확인하는 곳 |

`app/src/main/res/values/strings.xml`에 원래 용어를 쓰지 말고, 쉬운 말 문구를 기본으로 한다. 전문 용어가 꼭 필요하면 괄호로 병기한다.

## 4. 정보 구조 (IA)

### 4.1 하단 탭 4개 (0.2.0 개편 → 2026-10-03 여행 과정 길잡이로 다시 정리)

운영자 지적(2026-10-03): *"메뉴 구조가 여전히 조금 구분이 모호하고 … 여행 일정(생각 → 일정 검토 및 정리 → 각종 예약 → (반)자동 신청 등 처리 → … → 출국/입국 → 여행 → 복귀) 등의 과정이 제대로 안내 되고 그 흐름으로 처리되면 좋겠는데 현재 메뉴 구조는 그렇지 않아."*

문제: 앱에 **묶는 방식이 둘** 있었다 — 나라 중심(홈 → 나라 카드)과 시간 중심(내 여행 → 오늘 화면 → 체크리스트). 같은 일에 길이 셋이었고, **예약은 집이 없었다**(설정 › 내 정보 안에만).
고친 방식: **둘러보기(어디 갈까)와 내 여행(여행 과정)으로 가른다.** 여행과 관련된 모든 일은 내 여행 탭의 **한 여행 화면** 하나에 모인다(4.3).

| 탭 | 역할 | 주요 화면 |
|---|---|---|
| 둘러보기 | 어디로 갈까 — 여행을 만들기 전의 '생각' 단계 | 사진 히어로 한 장(가치 문장 + 신뢰 표시 + **여행으로 가는 버튼 전부**), **나라 사진 카드 → 나라 화면**(여행 영상·쇼핑도 그 안) — 5.12 |
| 내 여행 | 여행 과정 전체 | 여행 목록(5.16) → **한 여행 화면**: 지금 할 일 + 번호 붙은 8단계 아코디언(계획·예약·서류·짐·출국·입국·여행 중·복귀) — 4.3, 5.1 |
| 도움 | 위기 대응 (항상 오프라인) | 현지어 문장 카드, 긴급 번호, 대사관, 이럴 땐 이렇게(여권 분실·아플 때), 어느 나라에서나(영사콜센터) — 5.11 |
| 설정 | 내 정보와 앱 설정 | '내 정보는 이 휴대폰에만 저장돼요' 배너, 내 정보(여권·예약 서류)·같이 가는 사람, 쉬운 모드·자녀 폰 모드, 챙길 일 알림(켬·끔·시각), 와이파이에서만 받기, 개인정보 안내·출처와 알림·사진·글꼴 출처·앱 정보 — 5.5, 5.15 |

- **나라 화면**(둘러보기 › 나라 사진 카드, 내 여행 › 계획 단계, 5.13): 대표 경치 머리글(찜 버튼·최종 확인일·저장 상태) + 그림 메뉴 `입국·비자 / 여행 정보 / 쇼핑`(누르는 버튼, 스와이프 없음).
  - 입국·비자: 정부 비제휴·제출은 직접 안내 → 비자 카드 → (비자가 필요한 나라만) 비자 온라인 신청 → 입국 카드 → 공항에 도착하면 → 들어갈 때 → 내 여행에 넣기.
  - 여행 정보: 현지에서 쓰는 도구(현지어와 긴급 번호 · 이동하기 · 여행 영상) → 전기 → 돈·안전 → 지도도 저장해 두세요. 여행 영상은 YouTube 영상 목록(5.14).
  - 쇼핑: 한국인이 많이 사는 물건 미리보기 → 쇼핑 리스트(5.8), 귀국 전 확인 한 줄 요약.
  - **여행에서 열면** 머리에 `이 여행 · 태국` 띠 한 줄 + `여행으로 돌아가기`(2026-10-03).
- 하위 화면(나라·영상·쇼핑·꼭 챙길 물건·내 정보 등)은 제목 왼쪽에 '이전 화면으로' 버튼이 있다(0.3.1). 탭 첫 화면에는 없다. 탭이 아닌 화면은 **들어온 탭**이 켜진 채로 둔다(같은 화면에 길이 여럿이라).
- 자녀 폰 모드(3.3): 하단 탭이 `입국 QR · 도움` 두 개가 된다.
- 지금 없는 화면: 요즘 인기 여행지(11.1, 순위 데이터 C3·C4 연결 뒤 켬 — 문구 15개는 보존, 운영자 결정 16번), 찜한 여행지 목록(찜은 나라 화면 머리글의 하트), 알림 설정·오류 제보·여행사 소개(2차). **여행 준비 탭 화면은 2026-10-03에 없앴다** — 입국 서류 카드와 꼭 챙길 물건이 나라 화면·한 여행 화면과 똑같이 두 번 있었다.
- 도움 탭 아이콘·라벨은 다른 탭과 구분되는 따뜻한 색(#A8431A)으로 항상 표시한다.

### 4.2 여행 단계 (8단계) — '내 여행' 탭이 단계에 맞춰 자동 전환

| 단계 | 시점 | 앱이 알아서 하는 일 | 사용자가 하는 일 |
|---|---|---|---|
| ① 꿈꾸기 | 언제든 | 찜한 여행지를 Wi-Fi에서 자동 저장 | 찜하기 |

- 파기 전에는 "사진·영수증은 남고 여권 정보만 지워요"라고 설명하고 '미루기' 버튼을 둔다.

### 4.3 여행 과정 8단계와 기한 — **서로 다른 두 축** (2026-10-03)

4.2의 여행 단계는 '앱이 알아서 하는 일'을 적은 표다. 사용자가 보는 **묶음**은 아래 여덟 단계이고, **언제까지**는 따로 둔 축이다.

| 축 | 값 | 무엇을 정하는가 |
|---|---|---|
| **단계** (무엇을 하는 일) | 계획 · 예약 · 서류 · 짐 · 출국 · 입국 · 여행 중 · 복귀 | 체크리스트 묶기, 단계 카드 번호(1~8), 지금 할 일 |
| **기한** (언제까지) | 한 달 전쯤 · 일주일 전 · 3일 전 · 출발하는 날 · 도착하면 · 여행 중 · 돌아오기 전 · 돌아와서 | 기한 날짜, 늦음 표시, 챙길 일 알림(6.1) |

- 두 축은 **독립**이다: 같은 `짐` 단계 안에 기한이 `일주일 전`인 항목(해외 결제 카드)과 `3일 전`인 항목(현지어 카드 미리 보기)이 함께 있다.
- **기한·늦음·알림 규칙은 2026-10-02와 똑같다.** 바뀐 것은 묶는 방식뿐이다.
- 단계마다 무엇을 하는지: ① **계획** 어디로 언제 갈지·내릴 공항 ② **예약** 항공·숙소·보험·데이터(+ 예약 서류 넣어 두기) ③ **서류** 여권 정보 저장·비자 신청·입국 카드 내기 ④ **짐** 꼭 챙길 물건·오프라인 자료·현지어와 긴급 번호 ⑤ **출국** 출국 순서·도착 공항 미리 보기·`도착했어요` ⑥ **입국** 공항 도착 순서 ⑦ **여행 중** 숙소로 돌아가기·현지어·보여 주기·쇼핑 ⑧ **복귀** 담아 둔 물건·귀국 전 확인·여권 정보 지우기.
- **지금 단계**: 떠나기 전에는 날짜가 아니라 **아직 안 끝난 첫 준비 단계**(계획 → 예약 → 서류 → 짐)다. 떠난 뒤에는 날짜가 정한다.
- 팩 데이터: `checklist[].stage`(단계) + `checklist[].phase`(기한). 단계 값이 없는 **예전 서명 팩**은 기한 이름에서 단계를 옮겨 온다. 체크는 항목 id에 붙어 있어 묶음이 바뀌어도 남는다(ARCHITECTURE 10.4b).

## 5. 화면 명세 (와이어프레임 기준)

공통 (디자인 개편 2026-10-01, 값은 8.4):
- 배경 #F4F5F7, 카드 흰색. 정책·정보 카드 하단에 `출처 [기관] · 최종 확인 YYYY.MM.DD`. 출처 줄은 접힘 안에 넣지 않고, 출처가 여럿이면 기관별로 한 줄씩·날짜는 같으면 한 번. 대기 중 값은 `[ ]` 자리표시로 개발하고 실제 데이터로 교체.
- **모서리 (D3, 운영자 결정 4번)**: 태그 8 · 입력칸·배지 12 · 버튼·타일 16 · 카드 20 · 히어로·대화상자 28 (dp). 완전히 둥근 알약 모양은 칩·인디케이터에만. (예전 문구 '모서리 14~20dp'를 바꿈)
- **카드 경계 (D2, 운영자 결정 6번)**: 흰 정보 카드 = 아주 옅은 1dp `LineSoft`(#E3E6EB) 테두리 + 부드러운 그림자. 상태 카드(주의·위험·성공) = 그림자 없이 연한 바탕 + 왼쪽 4dp 색 막대. 사진 카드 = 그림자·테두리 없음. 입력칸·꺼진 스위치 등 조작 요소 경계 = 1dp `LineStrong`(#6B7589).
- **카드뉴스형**: 정보 카드는 아이콘 → 큰 값(숫자·예/아니오) → 한두 줄 → 출처 순서. 숫자 타일은 팩에 구조 필드가 있을 때만 만든다(정책 값을 앱에 적어 넣지 않음). 세로 목록과 2열 그리드만 쓰고 가로 캐러셀은 쓰지 않는다. 쉬운 모드·큰 글자는 1열.
- 누를 수 있는 보조 버튼은 항상 테두리가 있고, 누를 수 없는 안내 띠는 흰 바탕 + 왼쪽 막대다(D21). 주 버튼(파란 채움)은 화면당 하나, 지우기는 빨간 버튼 + 확인 대화상자(D8).

### 5.1 한 여행 화면 (내 여행 › 여행 열기, 2026-10-03)

이 여행의 **모든 것**이 이 한 화면에서 닿는다. 예전 '오늘' 화면과 '여행 체크리스트'를 합친 것이다.

- 맨 위: 오프라인일 때 남색 배너 "인터넷 없음 · 저장해 둔 정보로 보여 드려요".
- 헤더: 큰 제목 "태국 여행" / 부제 "11월 3일 ~ 7일 · 4박 5일".
- 나라 사진 머리: 전체 진행 `12 / 30` + 막대 + 지금 단계 칩.
- **여행 과정 8단계 아코디언** (2026-10-03 2차): 번호 붙은 단계 카드 여덟. 머리에 번호 배지 + 이름 + 언제까지 + 진행(`3 / 7` + 막대), 지금 단계는 `지금`. 머리를 누르면 **그 자리에서** 펴지고 펼쳐져 있던 단계는 접힌다(한 번에 하나). 접혀도 머리는 모두 남는다. 예전 그림 격자 단계 막대는 없앴다.
- **지금 할 일**(파란 카드, 화면에 하나뿐인 주 버튼): 가장 급한 안 한 일 하나 + 그 단계로 가는 버튼. 다 했으면 지금 단계 이름과 `이 단계는 다 했어요`.
- 알림 한 줄: 다음에 언제 알려 주는지 + `이 여행만 조용히 두기`(6.1).
- **단계 카드 여덟**: 머리(단계 아이콘·이름·언제까지·`3 / 7`·막대) → 그 단계 항목들 → **그 단계에만 있는 안내**
  - 계획: 나라 안내 · 날짜·공항 고치기(그림 모자이크)
  - 예약: **묵는 곳**(날짜별로 여러 숙소 — 5.16) · **예약 서류 넣어 두기**(예약 서류 가져오기 — 2026-10-03에 설정 › 내 정보에서 여기로 옮겼다)
  - 짐: 꼭 챙길 물건 자세히 보기
  - 출국: 출국 순서 다섯(공항 사진 카드) · 도착 공항 짧은 카드 · `도착했어요`
  - 입국: **도착한 날 묵는 곳**(이름·날짜·주소 크게 + `지도에서 보기`·`기사님께 보여 주기`) · 공항 도착 순서(+유심·환전·숙소) · `다 했어요` · `도착을 잘못 눌렀어요`
  - 여행 중: **오늘 묵는 곳**(숙소를 옮기는 날이면 오늘 묵는 곳으로 바뀐다) · 2×2 큰 타일 — 숙소로 돌아가기(→이동하기) · 현지어 카드(→도움) · 입국 QR 보기 · 쇼핑 리스트
  - 복귀: 담아 둔 물건 반입 확인 · 귀국 전 확인 **전체**(운영자 결정 10) · 여권 정보 지우기(+7일 미루기) · 정리를 마쳤으면 축하 카드
- 맨 아래: 내가 넣은 항목 → 급할 때는 도움 → `체크·여행은 이 휴대폰에만` → 이 여행 지우기.
- 다 끝난 지난 단계와 먼 뒤 단계는 머리·진행만 보이고 그 자리에서 펼친다(숨기지 않고 접기만).

### 5.2 입국 카드 3개 국어 확인 (나라 화면 › 입국·비자, 내 여행 › 서류 단계에서 열기)
- 제목 "태국 입국카드 확인", 설명 "앱이 서류를 보고 채웠어요. 맞는지 한 번만 확인해 주세요."

- **서류에서 가져온 값 묶음 카드**: 출처별 묶음(여권에서 / 항공권에서 / **묵는 곳에서**(2026-10-03, 예전 '예약 확인서에서') / 내가 적음) 머리 아래, 행마다 한글 라벨(크게) + `English · 현지어` 라벨(작게) + 값. (행마다 붙던 출처 칩은 묶음 머리로 옮김)
- **`주소는 넣어 드리고, 지역은 사이트에서 골라 주세요`**(2026-10-03): 숙소 주소를 넣어 준 나라에서, 주·구·동·우편번호처럼 사이트 목록에서 골라야 하는 칸이 남으면 안내 카드 하나 + 저장해 둔 숙소 주소를 그대로 한 번 더 보여 준다. 채우지 않은 칸을 채웠다고 말하지 않는다.
  - 예: 성(영문) · Family name · นามสกุล / 이름(영문) · First name · ชื่อ / 도착 날짜 · Date of arrival · วันที่เดินทางมาถึง
- **직접 골라 주세요 카드**(주황 테두리): 여행 목적 · Purpose of travel · วัตถุประสงค์การเดินทาง / 선택지 "관광 · Tourism · ท่องเที่ยว", "출장 · Business · ธุรกิจ".
- 안내: "확인하면 앱이 공식 사이트에 넣어 드려요. 보안 문자와 마지막 '제출'은 직접 눌러 주세요."
- 하단: 주 버튼 "맞아요, 입력해 주세요" → 자동 입력 / 보조 "고칠 곳이 있어요".
- 빈칸이 있으면 주 버튼은 누를 수 없고, 그 위에 '빈칸 N개 남았어요' + '첫 빈칸으로 가기'(D9).
- 현지어 라벨은 국가 팩에서 가져온다. 번역은 원어민 검수 후 반영(14장).
  - 참고(2026-10-01): 원어민 검수(QUESTIONS C10·C16·C17)는 **출시 전 할 일로 그대로 남아 있다**. 다만 화면의 '원어민 검수 전' 배지(입국 카드 현지어 표기·도움 문장 카드)는 운영자 결정(2026-10-01, 결정 2번)으로 보이지 않는다.

### 5.8.1 묵는 곳 (내 여행 › 예약 단계, 2026-10-03 운영자 요청)

운영자 요청: *"호텔 예약 정보도 관리하는 거지?"* → *"날짜별로 숙소가 달라질 수 있으니 이것도 고려해서 작업해줘. … 그리고 숙소는 구글 맵에서 바로 찾아볼 수 있도록 link 되도록 해줘."*

- **한 여행에 숙소 0~n곳**. 밤마다 다른 숙소여도 된다(11/3~11/5 호텔 A, 11/5~11/7 호텔 B). 숙소 하나에 이름 · 주소(현지 글자) · 한국어 주소 메모 · 체크인·체크아웃 · 예약번호 · 숙소 종류 · **좌표** · 전화번호 · 메모.
- **좌표(다듬기 S2, 2026-10-03 운영자 결정)**: `숙소 종류` 아래 **접어 둔** 칸 하나 — 안 넣어도 된다. `지도에서 정확한 자리를 찾을 때 써요.` 숫자 두 개(`13.75, 100.5`)도, 구글 지도 링크도 붙여 넣을 수 있고 **읽어 낸 값을 그대로 보여 준다**(못 읽으면 모르겠다고 말한다 — 지어내지 않는다). **앱 안에는 지도가 없다**(지도 라이브러리·키·네트워크 없음) — 지도에서 고르고 싶으면 구글 지도에서 링크를 복사해 붙여 넣는다고 화면이 말한다. `지도에서 좌표 확인`으로 넣은 좌표를 바로 확인할 수 있고, 좌표가 있으면 지도·기사님께 보여 주기가 **주소보다 좌표를 먼저** 쓴다.
- **예약 단계의 `묵는 곳` 카드**: 날짜 순으로 한 줄씩(이름 · `11월 3일 ~ 5일 · 2박 · 호텔` · 주소 한 줄 · `지도에서 보기` · `기사님께 보여 주기`), 누르면 고치기. 아래에 `숙소 추가`와 `예약 서류에서 가져오기`.
- **부드럽게 알려 주기(막지 않음)**: 날짜를 안 적은 숙소 · 숙소 사이 빈 날 · 날짜 겹침 · 도착한 날 묵을 곳 없음 · 여행 날짜 밖. 오류가 아니라 안내 한 줄이고, 저장은 언제나 된다.
- **지도**: 공식 Google 지도 주소만 쓴다(키·새 라이브러리 없음) — 찾기는 `maps/search/?api=1&query=`(좌표를 알면 좌표, 없으면 주소), 길찾기는 이동하기와 같은 `maps/dir/?api=1&destination=`.
- **한 번만 적는다**: 숙소를 저장하면 같은 id로 '가는 곳'(5.9)이 만들어지고, 주소를 비우거나 숙소를 지우면 그 가는 곳도 사라진다. 사람이 직접 넣은 가는 곳은 건드리지 않는다.
- **입국 카드**: 도착한 날 묵는 곳의 주소·이름·종류가 입국 카드 칸으로 들어간다(5.2 확인 화면의 `묵는 곳에서` 묶음). 주·구·동·우편번호는 사이트 목록에서 고르는 칸이라 **앱이 채우지 않고**, 확인 화면이 저장해 둔 주소를 보여 주며 "지역은 사이트에서 골라 주세요"라고 말한다.
- **저장 위치**: 주소는 개인정보에 가까워 여권·예약 서류와 같은 **암호화 보관함**에만 둔다. 화면은 캡처를 막고(FLAG_SECURE), 로그·알림·서버로 나가지 않는다. 체크리스트에는 주소 글자가 아니라 '주소를 적어 둔 숙소가 있다'만 적는다.
- **옮기기**: 예전 `lodging` 예약 서류는 보관함을 열 때 묵는 곳으로 옮겨진다(id 그대로, 이름·예약번호·날짜 유지). 주소는 예약 서류에 없어 비어 있고 사람이 채운다.
- **모아 보기(다듬기 S2)**: 설정 › 내 정보에 **모든 여행의 숙소** 목록을 둔다(5.5) — 넣는 자리는 여기 예약 단계 하나이고, 내 정보에서는 찾고 고치고 지운다.
- **숙소 종류는 비워 둔다(다듬기 S2 운영자 결정)**: 그 나라 사이트 선택지에 없는 종류(예: MDAC의 게스트하우스)는 **앱이 대신 고르지 않는다**. 앱이 짐작한 값은 사람 눈에 안 보이게 제출될 수 있기 때문이다. 비운 칸은 빈 필수 칸으로 세고(5.2 맨 위 빈칸 요약 · 주 버튼 막힘), 확인 화면이 왜 비웠는지 한국어로 말한다.

  - 박스보다 많으면 `여행 n개 모두 보기`가 내 여행 목록으로. 다녀온 여행이 있으면 `예전 여행지 다시보기`.
  - 채운 버튼은 하나 — 언제나 `새 여행 만들기`(여행으로 가는 길은 박스가 맡는다). 나머지는 테두리 버튼.
  - `예전 여행지 다시보기`는 내 여행 목록의 `지난 여행` 묶음을 펼친 채로 연다(지난 여행만 보는 화면은 따로 없다).
- 여행이 **있으면** 버튼 위에 그 여행 상태 한 묶음: `내 여행 · 태국` · `출발 3일 전` · 날짜 · `체크리스트 12 / 28` + 진행 막대.
  (예전에는 머리글 아래 따로 있던 카드다 — 2026-10-03 2차에서 여행마다 흰 박스로 갈랐다.)
- 나라 사진 카드: 여행 중인 나라(없으면 첫 나라)는 크게 1장, 나머지는 2열. 카드마다 비자 요약 칩 하나(예: '비자 없이 90일'), 목록 아래 출처 줄. 누르면 나라 화면(5.13) — 여행 영상·쇼핑·이동하기도 그 안에 있다.
- **급할 때 도움은 탭 막대의 도움 탭**이다 — 둘러보기 안에 있던 `급할 때는 도움` 줄은 같은 길이 두 개여서 지웠다(2026-10-03 운영자 요청). 도움은 어느 화면에서나 탭 한 번.
- **여기 없는 것**(2026-10-03): 출국하는 날 순서 · 꼭 챙길 물건 · 귀국 전 확인 · 여권 등록 카드는 모두 내 여행의 그 단계로 옮겼다. 같은 일을 두 곳에서 하지 않는다.

### 5.13 나라 화면 (0.2.0, 비자 온라인 신청 0.2.1)
- 머리글: 대표 경치 사진 + 나라 이름 + 최종 확인일·저장 상태 칩, 뒤로·찜 버튼. 그 아래 `입국·비자 / 여행 정보 / 쇼핑` 전환 버튼(누르면 바뀜, 스와이프 없음).
- **입국·비자**:
  - ① 정부 비제휴 안내 + "마지막 제출은 직접 눌러요"(첫 항목, 8.1).
  - ② 비자 카드(흰 카드): 결론 문장(팩 `visa` 값) + 숫자 타일(머무를 수 있는 날, 입국 카드 비용 등 — 팩 구조 필드에서만) + 출처. 입국 카드 제출 기간 타일은 아직 그리지 않는다(D11, 아래 참고).
  - ③ 입국 카드(양식) 카드: 이름·비용·내는 기간 글 행 + '입력 도와받기'(레시피가 있는 양식 → 5.2) 또는 '입력할 값 준비하기'(레시피 없는 양식 → 값 복사해서 넣기).
  - ③b **의무가 아닌 사전 신고**(팩 `forms[].optional` — 지금은 베트남 사전 입국 정보 PAI, 2026-10-03): 같은 양식 카드이지만 제목 아래 `꼭 내야 하는 건 아니에요` 알약, eyebrow `권장하는 사전 신고`, 버튼은 보조 `미리 준비해 두기`, 설명은 "의무는 아니지만 공식 안내가 내기를 권해요 … 앱이 칸을 대신 채워 주지는 않아요"(레시피를 두지 않는다). 체크리스트 할 일·오늘 단계·알림의 '입국 카드'로는 세지 않는다 — 기한 있는 할 일처럼 보이면 안 된다.
  - ④ **비자 온라인 신청**(한국 일반 여권으로 비자가 필요한 나라만 — 지금은 인도네시아 e-VOA): '1단계 입국 신고(All Indonesia, 주 버튼) → 2단계 비자 신청(e-VOA, 보조 버튼)' 순서로 보인다. 신청 순서·요금(IDR 500,000, 환불 불가)·가짜 사이트 경고(빨간 띠)·"앱은 입력 칸만 채워 드려요. 신청 버튼과 결제는 직접 하세요"·출처(주인도네시아 대사관 공지). 입력은 기존 All Indonesia 자동 입력이 돕고, 신청 버튼·결제·캡차는 사람이 한다(ARCHITECTURE '비자 온라인 신청').
  - ④b **공항에 도착하면** (2026-10-03, 운영자: "각 국가별 공항에서 입국 신고하는 위치를 안내"): 입국 카드 카드 다음 카드뉴스 한 장 — 공항 이름 칩(둘 이상일 때, 처음 = 부른 곳이 준 공항 → 이 나라 여행의 내리는 공항 → 팩 첫 공항) → 공항 머리(이름·도시·코드·영어 이름) → 번호 단계(단계마다 kind 아이콘, 공식 안내에 적힌 위치만 위치 칩, 짧은 설명) → 입국 심사(또는 form_check) 단계 안 노란 강조 줄 `TDAC를 내고 받은 접수 확인 메일을…`(입국 카드를 어디서 보여 주는지) → 한국 여권 자동 출입국 심사대 줄(공식 안내가 한국 여권을 콕 집어 밝혔을 때만 ✅/❌, 모르면 숨김. 자동 심사대 줄은 `egate` 단계 안에, 없으면 입국 심사 단계 안에 — 조건이 있는 나라는 그 단계 제목이 조건을 먼저 말한다: 대만 `자동 심사대(e-Gate)는 등록부터`, 베트남 `자동 심사대는 베트남 국민용`) → `공식 안내 페이지 열기`(브라우저) → 출처. 팩에 공항이 없으면 카드가 없다.
    - 판정을 모르는데(`egate_kr: null`) 공식 안내끼리 다른 나라는 `…쓸 수 있는지는 공식 안내가 분명하지 않아요`(물음표) 줄 + 두 안내를 그대로 적은 메모(인도네시아: 공항 안내 ↔ 이민국 2024년 발표). 판정도 메모도 없으면 줄 자체가 없다(일본·중국·태국).
  - ⑤ 들어갈 때(팩 문장, 뜻 없는 점 불릿) + 출처 → ⑥ '여행 계획 만들기'(이 나라를 미리 골라 둠).
  - 태국 TDAC 제출 기간 문장은 외교부 해외안전여행 원문("입국하는 날을 포함하여 입국 전 3일 이내", 2026-10-01 확인)에 맞춰 팩을 고쳤다(TH 팩 2026.10.01-1, 배포는 main 머지 때).
- **여행 정보**: (여행경보 문장이 있으면 맨 위 빨간 띠) → 현지에서 쓰는 도구 타일 4개(현지어와 긴급 번호 → 도움 탭, 이동하기 → 5.9, 여행 영상 → 5.14, 오프라인 지도 → 아래 지도 카드) → 전기(한국 플러그가 맞는지 결론 + 플러그·전압·주파수) → 돈·안전 → 지도도 저장해 두세요.
- **쇼핑**: 한국인이 많이 사는 물건 3개 미리보기(분류 아이콘·반입 판정·출처) + '쇼핑 리스트 보기'(5.8) → 귀국 전 확인(한 줄 요약 + 펼치기).

### 5.16 내 여행 목록·여행 체크리스트 (2026-10-02 운영자 요청)

- **내리는 공항 (2026-10-03)**: 여행 만들기·고치기에 `내리는 공항`(그 나라 팩 `airports`에 있는 공항 칩 + `아직 몰라요`, 팩에 공항이 없으면 칸 없음). 저장값은 IATA 코드뿐(개인정보 아님, 예전 저장본은 '모름'). 출국하는 날에는 `도착하면 이 순서예요`(짧은 공항 카드), 도착 단계에는 그 공항 순서. 체크리스트 '도착하면'에 `도착 공항 순서 보기`(팩에 공항이 있을 때만 — 나라 화면 공항 묶음으로 바로 내려간다).

> "여권 만료 기간 확인부터 시작해서 전체 여행 과정에서 챙겨야 하는 사소한 것들까지 Check List로 Check해서 빠지지 않도록 관리할 수 있도록 해 주고, 같은 나라라도 여러번 갈 수 있으니 일정에 따라 서로 다른 여행이라고 판단하고 새로운 Check List를 관리할 수 있도록 해줘."

- **내 여행 목록** (내 여행 › 여행 목록 보기, 홈 여행 카드 `여행 n개 모두 보기`): 여행 중 → 다가오는 여행 → 지난 여행(접어 둠). 줄마다 나라 사진 원형 썸네일 + 나라 + 날짜 + 상태(출발까지 n일·여행 중·다녀왔어요) + `체크리스트 12 / 30` 막대. 날짜가 겹치는 여행은 막지 않고 맨 위 한 줄 + 그 줄에 `날짜가 겹쳐요`. 주 버튼 `새 여행 만들기`(새 여행을 만들면 바로 그 체크리스트로).
- **나라 화면 `내 여행에 넣기`** = 그 나라 **새 여행**. 같은 나라로 가는 다가오는 여행이 이미 있으면 `새 여행으로 만들까요, 기존 여행을 열까요?`를 묻는다.
- **여행 체크리스트** (여행 하나 — 2026-10-03부터 **한 여행 화면**(5.1) 안에 있다): 나라 사진 머리(`12 / 30` + 막대 + 지금 단계) → 지금 할 일 → 번호 붙은 단계 카드 여덟(1 계획 · 2 예약 · 3 서류 · 4 짐 · 5 출국 · 6 입국 · 7 여행 중 · 8 복귀 — 접혔다 펴지는 아코디언, 단계마다 언제까지 + `3 / 7` 막대 + 그 단계에만 있는 안내) → 내가 넣은 항목 → 이 여행 지우기.
  - 항목 종류: **앱이 확인** (여권 남은 기간·여권 넣어 두기·나라 안내 받아 두기·이 여행 입국 카드 제출·여권 정보 지우기 — `앱이 확인했어요`, 사람이 바꿀 수 있음) / **팩 사실** (비자·머무는 기간, 입국 카드와 내는 기간, 꼭 챙길 물건 규칙, 영사콜센터·현지 긴급 번호, 귀국 면세·검역, 나라별 문장 — 출처·확인일, 팩에 사실이 없는 나라에는 만들지 않음) / **챙기기 안내** (예약 다시 보기·데이터·오프라인 지도·숙소 주소 현지어·공항 일찍·여권 따로 두기·남은 현금 등 — 숫자 없는 안내) / **내 항목** (글자만, 고치기·지우기).
  - 기간이 정해진 입국 카드는 기간이 열리는 날까지 잠김(`11월 1일부터 할 수 있어요`), 열리면 `입국 카드 준비하기`로 바로. 출발 당일까지 안 냈으면 그때만 빨강(`오늘 꼭 내요`). 기간이 없는 입국 카드(미리 안 내도 되는 것)는 빨강·늦음을 붙이지 않는다. 그 밖의 늦은 항목은 부드러운 주의 태그(`지금 해 두세요`) — 떠나기 전·도착 단계만.
  - 한 일은 제목·태그만 남기고 설명을 접는다. 다 끝난 지난 단계와 먼 뒤 단계는 머리·진행만 보이고 그 자리에서 펼친다(숨기지 않고 접기만).
  - 여권 남은 기간: 나라 팩 `requirements[].passport_validity`(공식 출처) 기준으로 지갑을 열 때 앱이 판단 — 괜찮으면 체크, 모자라면 `이 여행에는 여권 남은 기간이 입국일 기준 6개월 이상 필요해요. 지금 여권으로는 모자라요 — 여권 재발급을 먼저 알아보세요` + 외교부 여권 재발급 안내. 기준이 공식 안내에 없는 나라는 `나라별 기준을 공식 안내에서 확인하세요` + 외교부 해외안전여행. 여권이 없으면 손으로 체크하고 `여권 등록하기` 버튼.
- **지금 할 일**(한 여행 화면 맨 위): 가장 급한 안 한 항목 **하나**(급함 → 늦음 → 기한 순, 알림이 고르는 것과 같은 항목) + 그 항목이 있는 단계로 내려가는 버튼. 항목을 여기서 다시 그리지 않는다 — 길은 하나다.
- 체크 상태·내 항목·여행은 기기에만(백업 제외 DataStore). 못한 항목은 하루 한 번 **여행마다** 알린다(6.1 챙길 일 알림, 2026-10-03) — 한 여행 화면에 다음 알림 시각과 `이 여행만 조용히 두기`가 있다. 새 권한은 없다.
- 알림은 **기한 축**만 본다(4.3) — 묶는 단계가 바뀌어도 알리는 항목·때는 그대로다.

## 6. 입국 서류 자동 처리 흐름

1. 제출 가능일 알림: "태국 입국 카드를 오늘부터 낼 수 있어요". (로컬 알림, WorkManager — 6.1 챙길 일 알림의 한 가지)
2. 3개 국어 확인 화면(5.2):
   - 서류에서 온 값 → **묶어서 1번 확인**
   - 추정값·선택값(목적 등) → **개별 선택**
   - 세관·건강 질문 → **그림 + 예/아니오로 직접 답변**
3. "맞아요, 입력해 주세요" → WebView에서 레시피대로 입력(5.3). 공식 사이트 위에 한글 말풍선 오버레이.
4. 사람 확인 지점(2.2)에서 멈추고 안내한다.
5. 사용자가 최종 제출 → 확인번호·QR·PDF를 기기 안(입국 때 보여 주기)에 저장, 홈 위젯 갱신.
6. 레시피 실행 실패(선택자 없음 등) → 즉시 수동 모드로 전환(화면 문구 '값 복사해서 넣기': 값 복사 버튼 + 공식 사이트) + 익명 실패 리포트 전송(9.4).

### 6.1 챙길 일 알림 (2026-10-03 운영자 요청 — "체크하지 않으면 알림으로 알려서 빼먹지 않도록")

하루 한 번(설정에서 고른 시각, 기본 아침 9시) 앱이 **여행마다** 체크리스트를 다시 만들어 못한 일을 알린다. 앱을 열지 않아도 돈다(WorkManager 주기 작업).

- **알리는 것** (여행 하나에 알림 하나, 하루 한 번):
  ① 입국 카드를 낼 수 있는 기간이 **오늘** 열렸는데 아직 안 냈다 — `태국 입국 카드 (TDAC)를 오늘부터 낼 수 있어요.`
  ② 기한이 지났는데 아직 안 한 항목이 있다(체크리스트 화면의 `지금 해 두세요`와 같은 규칙) — `아직 못한 일이 3개 있어요 — 여권 남은 기간 확인하기 외 2개`
  ③ 출발 7일·3일·1일 전인데 지금 단계까지 못한 일이 남았다 — `출발까지 3일이에요. 아직 못한 일이 2개 있어요 — …`
- **알리지 않는 것**: 지금 단계까지 다 했을 때 · 아직 열리지 않은 뒤 단계 · 아직 할 수 없는 항목(입국 카드 기간 전) · 기간이 정해지지 않은 입국 카드(미리 안 내도 되는 것) · 돌아온 뒤 '여행 중·돌아오기 전·돌아와서' 단계 · 알림을 꺼 둔 여행 · 오늘 이미 알린 여행. 한 여행에 하루 두 번은 없다.
- **알림 모양**: 제목 `태국 여행 · 11월 3일 출발`, 본문은 위 문장. 누르면 **그 여행의 체크리스트**가 열린다(여행 id만 넘긴다). 여행마다 알림 번호·묶음(setGroup)이 달라 여행이 여럿이어도 서로를 지우지 않는다. 통로는 `챙길 일 알림`(도착·안내 변경은 그대로 `여행 알림`).
- **개인정보**: 알림 글에는 이름·여권 번호·생년월일이 들어가지 않는다. 항목 제목은 서명된 색인 틀·나라 팩에서 온 글만 쓰고, **내가 넣은 항목(사람이 쓴 글)은 알림에 담지 않는다**. 판단에 쓰는 값은 모두 이 휴대폰 안(여행 장부·체크·팩)이고 밖으로 나가지 않는다.
- **설정 › 알림**: 챙길 일 알림 켬·끔 · 알려 줄 시각(아침 8시 / 아침 9시 / 저녁 8시) · 휴대폰 알림 권한이 없으면 안내 줄 + `휴대폰 알림 설정 열기` · `알림은 이 휴대폰에 있는 여행과 체크만 읽어요` 한 줄. 기본은 켬.
- **여행 체크리스트 화면**: 머리 아래 `못한 일 알림` 한 줄 — 다음에 언제 알려 주는지(`못한 일이 있으면 내일 아침 9시에 알려 드려요`)와 **이 여행만 조용히 두기** 스위치.
- 새 권한은 없다(POST_NOTIFICATIONS는 이미 있다). Android 13+ 권한이 없으면 알리지 않고 '오늘 알림' 기록도 남기지 않는다(권한을 켜면 그날부터 다시 알린다).

### 6.2 공지 알림 (앱 푸시, 2026-10-08 운영자 요청 — "App Push를 할 수 있는 기능")
- 운영자가 `tools/notices/notice.py push --id … --target all|TH --send`(또는 Actions › notices › Run workflow)로 보낸다. 서버 로직 없이 GitHub Actions가 FCM HTTP v1로 **토픽**에 보낸다 — `notice_all`(공지 알림을 켠 기기), `notice_promo`(광고성 소식에 동의한 기기), 나라별은 그 나라 토픽과의 조건.
- 메시지에는 글이 없다(공지 id만). 앱이 서명된 공지를 받아 **그 제목·첫 쪽**으로 알리고, 못 받으면 `새 소식이 있어요`(누르면 공지사항). 누르면 그 공지가 열린다. 통로 `공지·소식`(챙길 일 알림과 따로 끈다).
- 알리지 않는 것: 자녀 폰 모드, 공지 알림 꺼짐, 광고 동의 없음, 기간 밖·다른 나라·다른 앱 버전, 다시 보지 않기를 누른 공지.
- **광고성 정보(8.2 정보통신망법 제50조)**: 동의(기본 끔) · 제목 `(광고)` · 받지 않는 방법을 알림·대화상자에 · 21시~8시는 `밤에도 받기`에 따로 동의한 경우만(아니면 **아침 8시까지 미뤘다가** 그때 다시 확인 — 한국 시각과 휴대폰 시각 둘 다 낮일 때) · 동의·철회하면 결과(보내는 곳·처리한 날)를 바로 보여 준다.
- 토큰·열람·클릭 기록을 서버에 두지 않는다. 동의 날짜·보지 않기 기록은 이 휴대폰에만.

## 7. 개인정보·보안 설계 (필수)

### 7.1 원칙
- 여권·예약 서류·개인 프로필 등 개인정보(PII)는 **운영자 서버(Firebase 포함)로 절대 보내지 않는다**.
- PII가 기기 밖으로 나가는 유일한 경로: 사용자가 실행한 자동 입력으로 **허용 목록에 있는 정부 공식 도메인(HTTPS)**에 제출될 때.

### 7.2 문서 인식
- **여권**: ML Kit Text Recognition v2 **번들형**(모델을 앱에 포함)으로 MRZ 인식 → ICAO 9303 체크디지트 검증.
  - ML Kit은 이미지 등 입력 데이터를 기기 안에서 처리한다. 다만 API 성능·사용량 메트릭을 Google로 보내므로 개인정보 안내에 고지한다 `[재확인]`.
- **NFC 칩 검증(2차)**: JMRTD로 BAC/PACE 접속 → DG1 읽기 → SOD 전자서명 검증. **DG2(얼굴 사진)는 읽지 않는다**(생체정보 이슈 회피).
- **숙소·항공 서류**: 촬영 OCR + 규칙 기반 추출(날짜·예약번호 정규식). 가능하면 다른 앱의 '공유하기'로 PDF·텍스트를 받는 경로를 우선한다. 지원 기기에서는 기기 내 LLM(Gemini Nano, ML Kit GenAI) 보조를 선택적으로 쓴다. 실패 시 수동 확인.

### 7.3 저장
- Android Keystore 기반 AES-GCM 암호화 + 생체 인증 잠금.
- 원본 이미지는 값 추출 직후 삭제.
- 자동 백업 제외(`android:allowBackup`/`dataExtractionRules`), 민감 화면 `FLAG_SECURE`.
- 여행 종료 후 자동 파기 옵션(파기 전 설명 + 미루기).
- 여권 사본 보관은 사용자 선택(기본 끔), 암호화.

- **여권 남은 기간 (2026-10-02)**: 만료일은 지갑(Keystore AES-GCM)을 연 그 순간 메모리에서만 쓰고, 여행마다 **결과만**(`ok`/`short`/`unknown` + 기준 달 수·기준일 종류) 기기 안 여행 장부에 남긴다. 만료일·여권 번호는 새로 저장하지 않고 로그·알림·서버에 넣지 않는다. 체크리스트는 여권 값을 보이지 않으므로 FLAG_SECURE 화면이 아니다(여권 값을 보이는 화면은 그대로 FLAG_SECURE + 보안 배너).

### 7.4 권한·SDK
- 사진은 **Photo Picker**(저장소 권한 불필요). 카메라는 촬영 시에만.
- 교통 앱 설치 확인은 `QUERY_ALL_PACKAGES`를 쓰지 말고, 매니페스트 `<queries>`에 필요한 패키지만 선언한다.
- 분석·크래시 SDK가 입력 화면 내용이나 WebView 로그를 수집하지 않게 막는다. Analytics 이벤트에 여권·여행 일정 등 PII를 넣지 않는다. 광고 ID 수집을 끈다.
- 클립보드 복사 후 일정 시간 뒤 지우기 옵션.

### 7.5 레시피 보안
- 레시피는 **선언형 데이터(JSON)만** 허용한다. 원격으로 받은 JavaScript를 실행하지 않는다. (레시피 서버가 탈취되면 보관함을 읽어 외부로 보내는 경로가 생기기 때문)
- 모든 국가 팩과 레시피는 서명(Ed25519 권장)하고, 앱에 내장한 공개키로 검증한 뒤 적용한다.
- 레시피는 `official_url_patterns`에 일치하는 HTTPS 페이지에서만 실행한다.

### 7.6 신뢰 증명
- 문서 인식·보관함·입력기 핵심 모듈은 공개 저장소로 공개하는 것을 전제로 작성한다(12.6절 브랜치 보호와도 연결).

## 8. 정책·법률 요구사항

### 8.1 Google Play
- **오인 주장 정책**: 권한 없이 정부 서비스를 제공·중개하는 것처럼 보이면 안 된다.
  - 앱 이름·아이콘에 정부 연상 요소 금지. 입국 화면(나라 화면 › 입국·비자, 내 여행 › 여행 준비, 입국 카드 확인·자동 입력·값 복사해서 넣기)의 첫 항목과 스토어 설명에 "정부 기관과 제휴하지 않았습니다"를 고지한다. (예전 '입국 준비 탭 상단' — 탭 개편으로 위치를 옮김)
  - 정보 출처를 명시하고, 공식 사이트 화면을 그대로 보여주며, 사용자가 직접 제출한다.
- **접근성 API**: 공식 앱 조작용으로 쓰지 않는다. (자율 동작은 금지, 결정적 자동화도 고지·동의 필요 `[재확인]`)
- **데이터 보안 섹션**: 기기 안에서만 처리하는 데이터는 '수집'이 아니다. 다만 WebView로 정부 사이트에 제출되는 경로는 해석이 애매하므로 보수적으로 기재한다.
- **민감 정보**: 카메라·여권 처리에 대해 눈에 띄는 고지와 동의 화면을 둔다.
- **결제**: 수수료 링크는 앱 밖에서 쓰는 실물 상품·서비스라서 Play 결제 대상이 아니다.
- **타깃 API**: 최신 요구 수준을 확인하고 맞춘다 `[재확인]`.

### 8.2 한국 법
- **여권번호는 고유식별정보**다. 운영자 서버로 받지 않는 구조를 유지한다(받는 순간 별도 동의·암호화 의무 발생).
- **신고 책임은 신청자 본인**이다. OCR 오류가 입국 거부로 이어질 수 있으므로 원본 대조 화면이 필수다.
- **포지셔닝**: "대행"이 아니라 "본인 입력 보조 도구"로 표현한다. 무료 입국카드에 수수료를 받지 않는다.
- **수수료 링크(제휴 프로그램 링크)**: 표시광고법상 추천·보증 시 경제적 이해관계 표시 기준을 따른다(앱 표시는 '수수료 링크' 라벨 + 목록 맨 위 수수료 고지). 제휴 프로그램별 앱 게재 허용 여부와 표기 문구 규정을 확인한다 `[확인 필요]`.
- **보험·환전·카드**: 수수료를 받지 않는다. 보험 모집·금융상품 판매 중개 규제 대상이 될 수 있어, 법률 검토 전까지 공식 비교·안내 링크만 둔다.
- **가족 모드**: 동행자(미성년자 포함) 서류는 보호자 기기에만 저장하고, 등록 시 동의 확인 문구를 표시한다.
- **광고성 정보 전송(정보통신망법 제50조, 2026-10-08)**: 앱 푸시로 광고(이벤트·혜택)를 보낼 때 ① 미리 받기 동의(설정 `광고성 소식 받기`, 기본 끔) ② 제목 `(광고)` ③ 받지 않는 방법 표시 ④ 21시~다음 날 8시는 별도 동의(`밤에도 받기`) ⑤ 동의·철회 처리 결과 통지(보낸 곳·날짜·결과 — 앱 대화상자) ⑥ **2년마다 수신 동의 여부 확인 — 운영자 할 일**(서버에 동의자 목록이 없는 구조라 앱 공지로 다시 묻는다, `docs/NOTICES_PUSH.md` 5절) `[법률 검토]`. 서비스 안내(공지·긴급)는 광고가 아니어서 동의 없이 보내되, 광고 내용을 섞지 않는다.
- **안심 문구**: '유출 가능성이 전혀 없다' 같은 절대 표현을 쓰지 않는다(표시광고법·Play 오인 정책). 사실인 말 — `레디포트 서버에는 여권 정보가 아예 없어요`, `서버 해킹으로 새어 나갈 일이 없어요` — 과 정직한 단서(`휴대폰 잠금은 꼭 걸어 두세요`)를 함께.

### 8.3 콘텐츠 저작권
- 블로그·가이드북·여행사 페이지·커뮤니티 문장을 복제하지 않는다. 설명은 직접 작성한다.
- Wikivoyage·Wikipedia(CC BY-SA)를 쓰면 출처를 표기한다. 파생 콘텐츠도 같은 라이선스가 됨을 인지한다.
- 외교부 공공데이터(입국허가요건 등)는 이용허락범위 제한 없음 `[재확인]`.
- 지하철 공식 노선도 이미지는 저작권이 있으므로 공식 링크로 연결하거나 오픈데이터로 직접 도식화한다.
- 상품 포장 사진·브랜드 이미지는 쓰지 않는다(텍스트·아이콘). 특정 브랜드명도 중립성을 위해 쓰지 않는다.

## 11. 추가 서비스 상세

### 11.1 요즘 인기 여행지
- 데이터 `[재확인]`:
  - 인천국제공항공사 '항공사별 노선별 운송실적 정보조회' API: 매월 말일에 전월 기준 제공, 이용허락범위 제한 없음.
  - 한국공항공사 '전국공항 수송실적통계' API: 지방 공항 보완.
  - 네이버 데이터랩 검색어 트렌드: 실제 검색 횟수가 아닌 **상대 비율**만 제공. NAVER API HUB 종량제로 운영 중이므로 비용 확인 `[확인 필요]`.
  - 레디포트 찜 수(익명 집계): 이용자가 늘기 전까지 비중을 낮게.
- 초기 가중치: 여객 증감 50%, 검색 추이 30%, 찜 20%. 운영하며 조정.
- 필터: 비자 없이(입국 요건 데이터 재활용), 비행 시간, 이달에 좋은 곳, 가족 여행.
- ARIA가 주 1회 계산 → `rankings/latest.json` 배포. 오프라인 시 마지막 순위 표시. 기준 시점 항상 표시.
- 지금 상태: 공공 여객 통계 키(C3)·검색 추이 키(C4)가 없어 순위를 만들지 않는다(지어낸 순위 금지). 화면은 없고, 문구 15개(`rankings_*`)만 보존한다(운영자 결정 16번).

### 11.2 꼭 챙길 물건 + 구매 링크
- 꼭 챙길 물건 화면(5.10, 홈·내 여행 › 여행 준비에서 열기)의 체크리스트와 통합. '챙겼어요' → 준비 진행률 반영.
- 링크 원칙: 물건·여행 서비스만 수수료 링크(‘수수료 링크’ 표시 + 목록 상단 수수료 고지). 보험·환전·카드는 수수료 없이 공식 안내만.
- 추천 기준(목적지·계절·규정)으로 목록을 먼저 정하고, **수수료 때문에 순서를 바꾸지 않는다**.
- 가격은 저장하지 않는다. ARIA가 주 1회 끊긴 링크·품절을 점검해 교체 PR.

### 11.3 여행지별 한국인 인기 구매 상품
- 상품별 공식 통계가 없으므로: 관광청 쇼핑 안내·직접 조사로 후보 목록 → 네이버 검색 추이('도시 + 상품명') 상대 비교로 인기도 → 화면에 "한국인 검색 기준" 명시.
- 블로그·커뮤니티 수집 금지, 설명 직접 작성, 브랜드명·포장 사진 금지.
- 담은 목록은 ⑧ 귀국 단계에서 반입 가능 여부를 다시 확인. 면세 한도·반입 금지는 관세청·검역본부 공식 링크.
- 국가 팩에 포함되어 오프라인 동작.

### 11.4 여행사 소개 (2차)
- 목적지·유형별(패키지·자유여행·현지 투어) 목록, 선정 기준 공개, 수수료를 받는 여행사 링크에 '수수료 링크' 표시.
- 앱 안에서 예약·결제를 받지 않는다(여행업 등록 이슈). 외부 링크만.

## 부록 B. 이용 시나리오 (수용 테스트 기준으로 사용)

**A. 58세 부부, 첫 해외여행, 방콕 4박**
- D-45: 쉬운 모드, 방콕 찜 → Wi-Fi에서 팩 자동 저장
- D-20: 앱 준비 체크리스트로 Grab 설치·가입·카드 등록, 꼭 챙길 물건 확인
- D-3: 알림 → 3개 국어 확인에서 '관광'만 선택 → "맞아요" → 보안 문자·제출 → QR이 홈 위젯에
- 도착: 도착 모드 순서 카드, 입국심사에서 QR 제시
- 2일째: 인터넷이 끊겨도 '여기로 가기', 기사님께 보여주기 카드
- 귀국: 쇼핑 목록 반입 확인, 경비 정리, 여권 정보 파기 확인

**B. 중학생 자녀를 둔 4인 가족, 오사카 3박**
- 보호자 폰 가족 모드에 4명 등록, 일본 서류 한 번에 준비
- 자녀 폰은 자기 QR과 도움 탭만
- 지하철 타는 법 카드 + 지도 길찾기 연결
- 길을 잃으면 자녀가 '길을 잃었어요' 카드를 보여주고 보호자에게 전화

**C. 위기: 여권 분실**
- 도움 탭 → '여권을 잃어버렸어요' → 경찰 신고 → 대사관 연락 → 필요 서류 순서
- 사본 보관을 켜 둔 경우 암호화된 여권 정보 표시
